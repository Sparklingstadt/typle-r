# 単語パック 設計

- 日付: 2026-10-26
- 対象バージョン: v0.91.0 〜（下の「実装の分け方」の PR ごとに1つ上げる）
- 前提: v0.90.0。単語リストが最低単位で、任意の `group`（まとまり）・`levels`（難易度）・`category`・`tags` をリストごとに持つ

## 目的

単語リストより上に「単語パック」を置き、パックを選ぶ・練習する・作る・編集する・配布する・記録を見る単位にする。

- 単語リストは必ず1つの単語パックに属する。
- 単語パックは1つ以上の単語リストを持つ。

## 決定事項

| 項目 | 決定 |
|---|---|
| 範囲 | データ構造・編集・練習・配布・記録をこの spec にまとめる |
| `group`・`levels` | `group` をパックに置き換える。`levels` はリストに残し、パックの中で段階的に選ぶのに使う |
| `group` のないリスト | 移行で、1リストずつ同じ名前のパックにする |
| カテゴリ・タグ | リストからパックに移す |
| 保存形式 | `packs` 配列を別に持ち、リストは `packId` を持つ（下の「保存形式の比較」） |
| 記録 | リストごとのまま。画面でパックごとにまとめて集計する |
| 配布 | パックのファイルの書き出し・取り込み、公式パックのカタログ、パックの複製、リンクで共有 |
| ほかのアプリ（typle-ipad・typle-m・typle-a・typle-w） | 変更しない。保存しても壊れない互換だけを保つ |
| typle-kotlin-backend | README の約束どおり Go と同じ変更を入れる |

## 範囲外

- パックを通して全リストを続けて練習すること、その合計の記録
- ほかのユーザーとの比較・ランキング
- 公式パックの更新を、追加済みのパックに反映すること
- iPad・Mac・Android・Windows の画面でのパック表示（それぞれのリポジトリで後から行う）

## 保存形式の比較

| 案 | 内容 | 判断 |
|---|---|---|
| A | `{ version: 1, packs: [...], lists: [...] }`。リストに `packId` | **採用**。ほかのアプリと Go はリストの知らない項目を残す（`server/internal/workspace/extra.go`）ので `packId` は消えない。`packs` は別の列なので古いアプリは触れない |
| B | `{ version: 2, packs: [{ ..., lists: [...] }] }` | 所属が構造で保証されるが、古いアプリが読めなくなり、変換の層が要る |
| C | 各リストに `pack: { id, name, ... }` | パックの情報がリストの数だけ重なり、食い違う。空のパックを表せず、配布に向かない |

## 1. データ構造

### パック

```ts
type WordPack = {
  id: string
  name: string
  description?: string
  category?: string
  tags?: string[]
  /** 公式パックから追加したとき。 */
  origin?: { catalogId: string, version: number }
  createdAt: string
}
```

- `name`: 前後の空白を除いて1文字以上、200文字まで。ほかのパックと同じ名前は不可（比べ方はリスト名と同じく、前後の空白を除き `toLocaleLowerCase` で比べる）。
- `description`: 500文字まで。空なら保存しない。
- `category`・`tags`: 今のリストの規則（`normalizeLabels`、`MAX_CATEGORY`・`MAX_TAG`・`MAX_TAGS`）をそのままパックに使う。
- `packs` 配列の順番は保存順（作成順）。画面の並びは最近練習した順で、保存順は同じときの決め方に使う。
- パックの数の上限は、リストの数の上限と同じ。

### リスト

- `packId: string` を必ず持つ。
- `levels` は今のまま（1つ50文字・5段まで）。`group` は使わなくなり、保存しない。
- `category`・`tags` はリストに保存しない（パックに移る）。
- リスト名の重複は、同じパックの中だけで不可にする（今は全体で不可）。
- パックの中の順番は `lists` 配列の順番。
- パックには1つ以上のリストがある。最後のリストを消すとパックも消える。

### 保存先

- DB: `typle_workspaces` に `packs jsonb NULL` 列を足す。`NULL` はまだパック化していないデータ。
- ブラウザー保存（`typle-r:guest-workspace:v1`）: `{ version: 1, packs, lists }`。`packs` がなければ未変換。
- `decodeLists`・`encodeLists`（`src/core/wordLists.ts`）と Go の `workspace.Decode` はパックも読み書きする。パックの知らない項目も、リストと同じく残す。

### 変換（未変換のデータを読むとき）

TS（`src/core`）と Go（`server/internal/workspace`）に同じ規則で実装し、同じ入力のファイルで両方の結果が同じことをテストで確かめる。

1. `lists` を保存順に見て、`group` ごとに1つのパックを作る。
   - `id`: `pack-<そのgroupの最初のリストのid>`
   - `name`: `group`
   - `category`: そのgroupの最初のリストの `category`
   - `tags`: そのgroupの全リストの `tags` の和集合（最初に出た順。大文字小文字だけ違うものは最初のものを残す）
   - `createdAt`: そのgroupで最も古いリストの `createdAt`
2. `group` のないリストは1リストずつパックにする。`id` は `pack-<リストのid>`、`name` はリスト名、`category`・`tags`・`createdAt` はリストのもの。
3. `packs` の順番は、各パックの最初のリストが `lists` に出る順。
4. リストに `packId` を付け、`group`・`category`・`tags` を外す。
5. パック名が重なるとき（`group` 名と、`group` のないリストの名前が同じなど）は、3の順番で後のパックを「名前（2）」「名前（3）」…にする。
6. 同じパックの中でリスト名は重ならない（今はリスト名が全体で重ならないため）。

`id` を決まった形で作るので、Web と Go がそれぞれ変換しても結果は同じになる。最初の保存で `packs` が書かれ、以後は変換しない。

### 読み込み時の補正（変換済みのデータ）

古いアプリが保存したデータでも所属の規則を保つため、読み込みのたびに次を行う。

- `packId` がない、または存在しないパックを指すリスト: 変換の2と同じく1リストのパックを作る（`id` が `pack-<リストのid>` のパックがすでにあればそれに入れる）。
- リストが1つもないパック: 捨てる。
- リストに `category`・`tags`・`group` がある（古いアプリが付けた）: リストから外す。パックに `category`・`tags` がなければ、そのパックで最初のそのリストの値をパックに入れる。
- 同じパックの中でリスト名が重なる: 後のリストの名前を「名前（2）」…にする。

補正は保存時の検証より先に行うので、補正した結果がそのまま保存できる。

### 初期リスト（`src/plugins/packs`）

- `samples.json`・`countries.json`・`commands.json` は今の形のまま、各リストに `packId` を足し、`group`・`category`・`tags` を外す。
- パックの情報は新しく `packs.json` に置く（`catalogId`・`version: 1` を持つ。4節）。中身は、今の初期リストに上の変換をかけた結果と同じにする。
- `initialLists` と並べて `initialPacks` を出す。新しいアカウントとゲストは、すべての公式パックを `origin` 付きで持って始まる。
- Go の写し（`server/internal/workspace/packs/`）にも `packs.json` を足し、`go:generate` と `TestPacksMatchApp` に加える。
- typle-ipad・typle-w・typle-a の写しは変えなくても動く（`packId` を知らない項目として持つだけ）。写しを新しくするかは各リポジトリで決める。

## 2. 作る・編集する（Web）

### 単語パックの画面（`/words` を置き換える）

- 1パックを1行で表示する。名前・カテゴリ・タグ・リスト数・合計語数・練習の状況（5節の「練習済み 8/11」を含む）。今の `GroupRow` を広げたもの。1リストだけのパックも同じ形の行にする。
- 行を開くと中のリストを `ListRow` で並べる。リストごとの編集・書き出し・複製・削除は今までどおり。
- 検索はパック名・カテゴリ・タグ・中のリスト名から探す。リスト名で当たったパックは開いて表示する。
- 絞り込み（`LabelFilter`）はパックのカテゴリ・タグで行う。
- パックの操作: 練習・パックを編集・リストを追加・複製・書き出し・共有（ログイン時）・削除。
- 一覧の上に「新しいパック」「ファイルから取り込む」「公式パック」。

### パックの作成・編集

- `/packs/create`: パックの名前・説明・カテゴリ・タグと、最初のリスト（今のリスト編集と同じ欄）を1つの画面で作る。
- `/packs/edit?pack=<id>`: 名前・説明・カテゴリ・タグ（`LabelFields` をここへ移す）と、中のリストの並べ替え（ドラッグ。`SortableWordRow` と同じ仕組み）。
- 削除: パックを削除すると中のリストと記録もすべて消える。確認のダイアログでリスト数と記録数を出す。

### リストの作成・編集（`/create`・`/edit`）

- 「パック」の選択欄を足す。作成ではパックの「リストを追加」から開いたパックを選んだ状態にする（`/create?pack=<id>`）。パックを指定せずに開いたときは最後に使ったパック。編集ではほかのパックへ移せる。移した先で名前が重なるときは `listNameDuplicate`。
- `levels`（難易度）の欄を足す。1つ50文字・5段まで、順に入力する。
- カテゴリ・タグの欄は外す。
- 複製したリストは同じパックの最後に入る。名前の付け方は今の `duplicateList` と同じ（重なりはパックの中で判定）。
- CSV・TSV の取り込みでは、取り込み先として既存のパックか「新しいパック」を選ぶ。
- パックの最後のリストを削除するときは「パックごと削除されます」と確認する。

## 3. 選ぶ・練習する

- 練習画面の横の一覧と「単語リストを選ぶ」は、今の「まとまり」の表示をパックに置き換える。
- 並びは最近練習した順。パックの位置は、その中で最後に練習したリストで決まる。
- 1リストだけのパックは、選ぶとすぐそのリストで練習を始める。
- 複数のリストを持つパックは開いて選ぶ。`levels` を持つリストは今と同じく段階的なボタン（例: 基本 › 初級）、`levels` のないリストは名前のボタン。両方が混ざるときは `levels` のあるものを先にする。
- 検索と絞り込みは2節の一覧と同じ。
- 練習中のリストのパックは開いた状態にし、選んでいるリストを示す。
- 練習の単位はリストのまま。URL も `/play?list=<id>` のまま。
- ホームの「次に練習する」などリスト名を出すところは「パック名 › リスト名」にする（`levels` があれば「パック名 › 基本・初級」）。1リストだけのパックはリスト名だけ。

## 4. 配布・取り込み

### パックのファイル

- 名前: `<パック名>.typle-pack.json`
- 形:
  ```json
  { "format": "typle-pack", "version": 1,
    "pack": { "name": "…", "description": "…", "category": "…", "tags": ["…"] },
    "lists": [{ "name": "…", "levels": ["…"], "words": [{ "display": "…", "input": "…", "annotation": "…" }] }] }
  ```
- 記録・ID・作成日時・`origin` は含めない。
- 取り込むと新しいパックになる。ID は新しく決め、作成日時は今。パック名が重なれば「名前（2）」…。中身は保存と同じ規則で検証し、違反すれば取り込まない（エラーの理由を出す）。`format`・`version` が違えば `packFileUnreadable`。1MiB まで。
- リストごとの CSV・TSV の書き出し・取り込みは今のまま残す。

### パックの複製

- 中のリストを含めて丸ごとコピーする。記録・`origin` はコピーしない。名前は「名前（コピー）」（重なれば「（コピー2）」…。今の `duplicateList` と同じ付け方）。元のパックの直後に入れる。

### 公式パックのカタログ（`/packs/catalog`）

- 定義は `src/plugins/packs`（`packs.json` と各リストのファイル）。
- 全公式パックを並べ、`origin.catalogId` が同じパックを持っていれば「追加済み」、なければ「追加」。
- 「追加」で中身をコピーしてアカウントの最後に入れる（`origin` 付き、記録なし）。名前が重なれば「名前（2）」…。削除した公式パックもここから戻せる。
- `version` は持つだけで、更新の反映はしない。
- ログインしていないとき（ゲスト）も使える。

### リンクで共有（ログイン時だけ）

- テーブル `typle_shared_packs`:

  | 列 | 型 | 内容 |
  |---|---|---|
  | `id` | `uuid` 主キー | リンクの ID（ランダム） |
  | `owner_id` | `text` | 持ち主 |
  | `pack_id` | `text` | 持ち主のパックの ID |
  | `data` | `jsonb` | パックのファイルと同じ形のスナップショット |
  | `created_at`・`updated_at` | `timestamptz` | |

  `(owner_id, pack_id)` に一意インデックス。1パックにリンクは1つ。
- 「共有」でその時点の中身を写してリンクを作る。編集しても自動では変わらず、「共有を更新」で写し直す（リンクは変わらない）。「共有をやめる」で行を消す。共有中のパックを削除したら行も消す（保存 API が保存のときに消えたパックの行を消す）。
- パックの画面の行に「共有中」を出す。
- 公開ページ `/shared/<id>`: ログインなしでパック名・説明・ラベルと各リストの単語を見られる。持ち主の名前と記録は出さない。「自分のパックに追加」でファイルの取り込みと同じく追加する（ゲストはブラウザーに保存）。リンクがなければ「共有は終了しました」。
- Go のエンドポイント:
  - `PUT /api/workspace/packs/{p}/share` → `200 { id, url, updatedAt }`（作成・更新。保存済みのパックの中身を写す）
  - `DELETE /api/workspace/packs/{p}/share` → `204`
  - `GET /api/workspace/shares` → 共有中の `pack_id` と `id` の一覧
  - `GET /api/shared/{id}` → パックのファイルの形（認証なし。`Cache-Control: no-store`）。なければ `404 sharedPackNotFound`
- 書き込みはログインセッション（Cookie）とトークンのどちらでもよく、今の保存 API と同じ Origin とアカウントの確認をする。スナップショットは 1MiB まで。

## 5. 記録・ランキング

記録の保存はリストごとのまま。表示をパックでまとめる。

- 記録の画面（`/records`）: 絞り込みに「パック」を足す（リストの絞り込みの上の段）。各記録に「パック名 › リスト名」を出す。
- ベスト記録の画面（`/rankings`）: パックごとの見出しの下に、各リストのベスト記録を並べる。見出しにはパックの集計（練習回数の合計・練習済みのリスト数「8 / 11」・最後に練習した日時・7日以内に記録を更新したリストの数）。1リストだけのパックは今の1行の表示のまま。
- 単語パックの画面の各行に「練習済み 8/11」を出す。
- ホームの集計はリスト単位のまま、表示名だけ3節のとおりパック名を付ける。

## 6. API・サーバー

### DB マイグレーション

- `0024_packs`（PR 1）: `ALTER TABLE typle_workspaces ADD COLUMN packs jsonb NULL`
- `0025_shared_packs`（PR 6）: `typle_shared_packs` の作成（4節）
- データの変換は SQL で行わない（1節の変換をアプリと Go が読み込み時に行う）。

### アプリの保存 API（`/api/workspace`）

- 読み込みで `packs` を返す（`NULL` なら変換した結果）。保存で `packs` を受け取り、1節の規則で検証して `packs` 列に書く。
- 保存の大きさの上限（今の896KB の判定）は `lists` と `packs` を合わせて数える。

### 公開 API（`/api/v1`）

新しく:

| エンドポイント | 内容 |
|---|---|
| `GET /api/v1/packs` | パックの一覧。各パックに `listCount`・`wordCount`・`practiceCount`・`practicedListCount`・`lastPracticed`。`category`・`tag`・`q` で絞り込み |
| `GET /api/v1/packs/{p}` | パックと、中のリストの要約（`GET /api/v1/lists` の各項目と同じ形）を保存順で |
| `GET /api/v1/packs/{p}/export` | パックのファイル |
| `POST /api/v1/packs`（`-writable`） | `{ name, description?, category?, tags?, lists: [{ name, levels?, words }] }`（リスト1つ以上）→ `201 { pack }` |
| `PATCH /api/v1/packs/{p}`（`-writable`） | `{ name?, description?, category?, tags?, listOrder? }`（`listOrder` は中のリストの ID をすべて並べたもの）→ `200 { pack }` |
| `DELETE /api/v1/packs/{p}`（`-writable`） | 中のリストと記録ごと → `204` |
| `POST /api/v1/packs/{p}/copy`（`-writable`） | 本文なし、または `{ name? }` → `201 { pack }` |
| `POST /api/v1/packs/import`（`-writable`） | パックのファイルそのもの → `201 { pack }` |

既存のリスト API は互換を保つ:

- リストの応答に `packId` を足す。`category`・`tags` は所属するパックの値を返す。`GET /api/v1/lists` の `category`・`tag` の絞り込みもパックの値で行う。
- `POST /api/v1/lists`: `packId` を省略できる。省略するとリスト名で1リストのパックを作り、送られた `category`・`tags` をそのパックに付ける。`packId` を送ったときに `category`・`tags` も送ったら `400 invalidList`。`levels` も受け取る。
- `PATCH /api/v1/lists/{l}`: `packId` で移せる。`levels` を変えられる。`category`・`tags` を送ると所属するパックの値を変える。
- `DELETE /api/v1/lists/{l}`: パックの最後のリストならパックも消える。
- `POST /api/v1/lists/{l}/copy`: 同じパックに入る。`POST /api/v1/lists/import`: `packId` を指定でき、省略すると新しいパックを作る。
- `docs/api.md` を更新する。

### typle-kotlin-backend

Go と同じ変更（変換・補正・保存・API・共有）を入れ、`TYPLE_BACKEND=kotlin npm run test:e2e` を通す。別リポジトリの PR として、このリポジトリの対応する PR と同じ時期にマージする。

## 7. ほかのアプリとの互換

- typle-ipad・typle-m・typle-a・typle-w は変更しない。
- それらが保存しても、`packs` 列には触れず、リストの `packId` は知らない項目として残るので、パックの情報は消えない。
- それらで作ったリスト（`packId` なし）や、消したリストは、1節の補正で規則どおりになる。
- それらの画面では、リストのカテゴリ・タグ・まとめ表示が出なくなる（データは消えない）。README に書く。
- 確かめ方: 各アプリの core のテストの入力に、パック化した保存データを入れて読み書きを往復させ、`packId`・知らない項目が残ることを見る（各リポジトリでの一時的な確認で、そのリポジトリには変更を入れない）。

## 8. テスト

- 単体（`tests/*.cjs`）: 変換（`group` あり・なし・名前の重なり・タグの和集合）、補正（`packId` なし・存在しないパック・空のパック・リストに残ったラベル・パック内の名前の重なり）、検証、パックのファイルの読み書き、カタログの「追加済み」、複製の名前。
- Go: 変換と補正が TS と同じ結果になること（`tests/fixtures` の同じ入力を両方で読む）、新しい API、リスト API の互換、共有のエンドポイント、`TestPacksMatchApp`。
- E2E（Playwright）: パックの作成・編集・並べ替え・リストの移動・削除、練習画面での選び方、カタログからの追加、ファイルの書き出しと取り込みの往復、共有リンクを開いて追加、古い形（`packs` のないデータ）からの変換、ゲストのブラウザー保存での変換。
