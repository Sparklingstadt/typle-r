# 公式パックのフォロー 設計

- 日付: 2026-10-26
- 対象バージョン: v0.98.0
- 前提: v0.97.0。公式パックのカタログ（`/packs/catalog`）があり、「追加」で公式パックの中身をコピーして `origin: { catalogId, version }` 付きで入れる。新しいアカウントとゲストは全公式パックのコピーを持って始まる

## 目的

公式パックを「コピーして追加する」から「フォローする」に変える。

- Go のパックをフォローすると、自分のパック一覧に Go のパックが並ぶ。Kotlin も同じ
- フォロー中のパックには公式の更新がそのまま反映される
- アカウントは空で始まり、フォローしたパックだけが一覧に並ぶ

## 決定事項

| 項目 | 決定 |
|---|---|
| 方式 | 同期コピー方式。フォロー中のパックも普通のパック・リストとして保存し、読み込むたびに公式の内容へ揃える（下の「方式の比較」） |
| フォロー中のパックの編集 | できない（読み取り専用）。手を加えたいときは「複製」で自分のパックにする |
| フォロー解除 | パックをリスト・記録ごと消す。確認ダイアログを出す |
| 初期状態 | 新しいアカウントとゲストはパック 0 個で始まる |
| 既存のアカウント・ゲスト | 公式パックから来たパックを、編集の有無にかかわらずリスト・記録ごと消す。自分で作ったパック・取り込んだパック・複製したパックは残す |
| 同期の場所 | アプリ（TS）と Go の両方で、保存データを読むたびに行う |
| ほかのアプリ（typle-ipad・typle-m・typle-a・typle-w） | 変更しない。フォロー中のパックは普通のパックとして見える |
| typle-kotlin-backend | README の約束どおり Go と同じ変更を入れる（このリポジトリの範囲外。別リポジトリで行う） |

## 範囲外

- 解除したパックの記録を残して、再フォローで戻すこと
- フォロー中のパックの名前を公式の名前変更に合わせること（名前はフォローしたときのまま）
- iPad・Mac・Android・Windows の画面でのフォロー操作
- Go API からのフォロー（`POST` でフォローするエンドポイント）

## 方式の比較

| 案 | 内容 | 判断 |
|---|---|---|
| 1 同期コピー | フォロー中のパックを普通のパック・リストとして保存し、読み込むたびに公式の内容で置き換える | **採用**。練習・記録・ランキング・Go の読み取り API・ほかのアプリがそのまま動く |
| 2 参照 | `catalogId` と記録だけ保存し、単語は毎回カタログから引く | Go・Kotlin・各アプリがすべて参照の解決を持つ必要があり、対応前のアプリではパックが見えない。記録の置き場所も作り直しになる |

## 保存形式

```ts
type WordPack = {
  // …これまでの項目
  /** フォロー中の公式パック。followed のない origin は v0.98.0 より前のコピーで、読み込み時に消える。 */
  origin?: { catalogId: string; version: number; followed?: true }
}

type WordList = {
  // …これまでの項目
  /** フォロー中のパックのリストだけが持つ。公式のリストの id（src/plugins/packs の各リストの id）。 */
  origin?: { listId: string }
}
```

- パックとリストの `id` は、フォローしたときにランダムに決める（今の「追加」と同じ）。公式の id は `origin` だけに置く
- `version` は残すが使わない（中身を直接比べるため、上げ忘れても同期される）
- 古いアプリと Go は知らない項目を残す（`decodePacks`・`server/internal/workspace/extra.go`）ので、`followed` と `origin.listId` は消えない

## 読み込み時の変換

保存データを読むたびに、`normalizeLibrary`・`repairLibrary` の後で次の 2 つを順に適用する。TS（`src/core`）と Go（`server/internal/workspace`）で同じ結果にする。何度適用しても結果は変わらないので、移行のための印や SQL のマイグレーションは要らない。変換の結果は次の保存で書き込まれ、それまでも読む側には変換後の内容が見える。

### 1. 移行（古いコピーを消す）

次のパックを、そのリストと記録ごと取り除く。

- `origin` があり、`origin.followed` がないパック
- `origin` がなく、`id` が公式パックの `catalogId` のどれかと同じパック（`origin` ができる前のアカウントが持っている初期パック）

### 2. 同期（フォロー中のパックを公式に揃える）

`origin.followed` のあるパックごとに、`origin.catalogId` の公式パックを探す。

- 公式パックがない（カタログから外れた）: パックをリスト・記録ごと取り除く
- ある: パックの説明・カテゴリ・タグを公式の値にする。名前・`id`・`createdAt` は変えない
- リストは公式のリストの順に並べ直す。各公式リストについて
  - `origin.listId` が同じリストがあれば、名前・難易度・単語を公式の値にし、`id`・`createdAt`・記録は残す
  - なければ新しいリストを作る。`id` は公式のリストの id から決まる値（`<パックの id>:<公式のリストの id>`）にして、TS と Go が別々に変換しても同じになるようにする。記録はなし
- 公式にない `origin.listId` のリストと、`origin` のないリストは記録ごと取り除く
- ライブラリ全体のリストの並びでは、フォロー中のパックのリストを、そのパックの最初のリストがあった位置にまとめて置く

リストの数が `MAX_LISTS` を超えても許す（`applyChange` は保存済みの件数を保つ変更を許す）。

## 初期状態

- `src/plugins/packs/index.ts` の `initialLibrary` を空（`{ packs: [], lists: [] }`）にする。公式パックの定義は `officialPacks()` が `commands.json` などから作る（今の `initialLibrary` の作り方をカタログ側に移す）
- Go の `Initial()` も空のパック・リストを返す。公式パックの定義は `server/internal/workspace/packs/` に残し、同期に使う
- パック一覧（`/edit`）と練習画面（`/play`）は、パックがないとき「公式パックをフォローする」の案内と `/packs/catalog` へのリンクを出す

## 画面

### カタログ（`/packs/catalog`）

- 各公式パックに「フォローする」ボタン。押すと公式パックの中身で `followed: true` のパックをライブラリの最後に入れ、「◯◯をフォローしました」と通知して一覧に戻る
  - 名前が自分のパックと重なるときは「名前（2）」…（今の「追加」と同じ）
  - リスト数が `MAX_LISTS` を超えるときはボタンを無効にし、理由を出す（今と同じ）
- フォロー中なら「フォロー中」の表示と「開く」「フォロー解除」
- 「フォロー解除」は確認ダイアログ（「◯◯のフォローを解除します。このパックの記録も消えます」）の後、パックを削除する
- ログインしていないとき（ゲスト）も使える

### パック一覧・パック編集

- フォロー中のパックに「公式」のバッジを付ける
- 次の操作を出さない（ボタンを無効にするのではなく出さない）: パックの名前・説明・ラベルの編集、リストの追加・編集・削除・移動・並べ替え、パックの削除
- 代わりに「フォロー解除」を出す。動きはカタログと同じ
- 「複製」「書き出し」「リンクで共有」は使える。複製は今どおり `origin` を付けないので自分のパックになる。書き出しのファイルは `origin` を持たない（今どおり）

### そのほか

練習・記録・ランキング・ダッシュボードは変えない。フォロー中のパックも普通のパックとして動く。

## 編集の禁止（コア）

- `src/core/packEditing.ts` などの編集用の関数は、フォロー中のパックやそのリストを変えるとき `AppError('packFollowed')` を投げる。例外は、パックの削除（フォロー解除）と記録の追加・削除
- 保存（`applyChange`）は拒否しない。古いアプリが送った変更は、次の読み込みの同期で公式の内容に戻る

## Go バックエンド

- 読み込み時の変換（移行と同期）を `server/internal/workspace` に加え、ワークスペースを読む全 API で適用する
- 書き込み API のうち、フォロー中のパックやそのリストを変えるものは `409 packFollowed` を返す: `PATCH /api/v1/packs/{p}`、`POST /api/v1/lists`（`packId` がフォロー中のパック）、`PATCH`・`DELETE /api/v1/lists/{l}`、`POST /api/v1/lists/{l}/copy`、`POST /api/v1/lists/import`（`packId` がフォロー中のパック）
- 使えるもの: `DELETE /api/v1/packs/{p}`（フォロー解除）、`POST /api/v1/packs/{p}/copy`（自分のパックになる）、記録の追加・変更・削除
- `GET /api/v1/packs` などの応答の `origin` に `followed` が入る
- `docs/api.md` を更新する

## テスト

- コア（`node --test`）
  - 移行: `followed` のない `origin` のパック、`id` が `catalogId` のパックが消え、自分のパックは残る
  - 同期: 単語・難易度・説明・ラベルが公式に揃う。記録は `origin.listId` で引き継がれる。公式で増えたリストが加わり、消えたリストは記録ごと消える。カタログにないパックは消える
  - 何度適用しても同じ結果になる
  - フォロー・フォロー解除・編集の禁止（`packFollowed`）
  - `initialLibrary` が空
- Go: 同じ入力と期待値のフィクスチャ（`tests/fixtures/` に置き、TS と Go の両方のテストで読む）で変換を確かめる。書き込み API の `packFollowed`
- E2E（Playwright）: 空の状態の案内 → カタログでフォロー → 一覧に出る → 練習できる → フォロー解除で消える
