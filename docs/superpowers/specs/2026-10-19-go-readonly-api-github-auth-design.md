# 読み取り専用API（Go）のGitHub認証 設計

- 日付: 2026-10-19
- 対象バージョン: v0.40.0
- 前提: v0.39.0 の読み取り専用API（`docs/superpowers/specs/2026-10-19-go-readonly-api-database-design.md`）。起動時の `-owner` で1アカウントに固定し、認証はなかった

## 目的

GitHub のトークンで呼び出した人を確かめ、その人のアカウントのデータだけを返す。

## 決定事項

| 項目 | 決定 |
|---|---|
| 方式 | `Authorization: Bearer <GitHubのトークン>`。サーバーが GitHub の `GET /user` でユーザーIDを確かめ、`github:<ID>`（アプリの GitHub ログインと同じアカウントID）の行を読む |
| アカウント | トークンから決める。`-owner` は削除する。1つのサーバーで複数のユーザーがそれぞれ自分のデータを読める |
| サーバーの設定 | 秘密値・OAuth App は不要。トークンの権限も不要 |
| キャッシュ | 確認できたトークンを5分（トークンのSHA-256をキーに、最大1000件）。受け付けなかったトークンは覚えない |
| エラー | トークンがない・形式違い・GitHub が拒否は `401 invalidToken`（`WWW-Authenticate: Bearer`）。GitHub に届かない・レート制限・障害は `503 githubUnavailable` |
| 順序 | 未知のパス（404）と `GET`・`HEAD` 以外（405）は認証より先に返す |
| 公開 | 既定は `127.0.0.1`。ほかの端末から使うときは HTTPS のリバースプロキシの後ろに置く |

## 範囲外

GitHub 以外の認証、ブラウザーでのログイン画面、許可するユーザーの制限、開発用ログインのアカウント（`github:0`）、書き込み、本番へのデプロイ。
