# Typle API Implementation Plan

> この計画は実装済みの記録です。書かれている構成・パス・手順は当時のもので、今の構成は [README](../../../../README.md) を見てください。ここから作業を始めないでください。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/settings` で発行する個人用アクセストークンで、自分のアカウントの単語リストと練習記録を `/api/v1` から読み書きできるようにする。

**Architecture:** トークンは新テーブル `typle_api_tokens` に SHA-256 ハッシュで保存し、管理は Cookie セッション＋Origin 一致の `/api/tokens` だけで行う。`/api/v1` の各ルートは共通の `apiRoute` で Bearer 認証と scope を確かめ、書き込みは `workspaceRepository.modify` が「読み込み → core の純粋関数で変更 → 既存の `write`（revision の楽観ロック・共有同期）」を最大3回試す。入力の検証と応答の形は `src/core/apiRequests.ts`・`src/core/apiTokens.ts` に置く。

**Tech Stack:** Next.js 16.4（App Router の Route Handler）、React 19、TypeScript、Prisma 7 + PostgreSQL、Auth.js（next-auth v5）、next-intl、Playwright、`node --test`（`tests/*.test.cjs` + `tests/register.cjs`）

**Spec:** `docs/superpowers/specs/2026-10-10-typle-api-design.md`

## Global Constraints

- 書く前に `node_modules/next/dist/docs/` の該当ガイド（Route Handler、動的 `params` が Promise であること、`_` で始まるプライベートフォルダー）を読む（AGENTS.md）。最初に `npm ci` を行う。
- `src/core` は React・Next.js・Prisma・Node・ブラウザー API に依存しない。`src/plugins` は UI に依存しない。画面（`src/app`・`src/components`。`src/app/api` を除く）は `plugins/storage` を import しない（`eslint.config.mjs` が検査）。
- 画面の文言はコードに書かず、6言語（`ja`・`en`・`zh-CN`・`zh-TW`・`ru`・`fr`）の `src/messages/<言語>/*.json` に同じキーで入れる。アポストロフィは `’`。`ja` が型の基準。
- エラーは `AppError(<errors のキー>)`。API の応答は `{ "error": "<キー>" }`。
- トークン: `typle_` ＋ 32バイト乱数の base64url（43文字）。DB には SHA-256（16進）と先頭10文字の `prefix` だけ。`secret` を返すのは発行時の1回だけ。
- scope は `read` と `write`（`write` は `read` を含む）。期限は 30・90（既定）・365日・無期限（`null`）。1アカウント10個まで。名前は trim 後 1〜50文字。`last_used_at` は NULL または1時間以上前のときだけ更新。
- `/api/tokens` は Bearer では呼べない。`POST`・`DELETE` は Origin が `AUTH_URL`（未設定時はリクエストURL）のオリジンと一致、`POST` は `Content-Type: application/json`。
- `/api/v1` の応答は `Cache-Control: no-store`、CORS ヘッダーなし。書き込みの本文は JSON 必須（415）、1MiB まで（413）。
- 記録の取得は `limit` 1〜1000（既定100）。リストは1プロファイル100件、記録は1リスト10000件まで。
- マイグレーション `0005_api_tokens` はテーブル追加のみ（旧アプリと互換）。
- バージョンは `npm version 0.32.0 --no-git-tag-version`（package.json と package-lock.json の両方）。
- 各コミットの末尾に次の2行を付ける:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
  `Claude-Session: https://claude.ai/code/session_01HDRr8UbHjTVc5KgMxN8A6S`
- DB テストと E2E には PostgreSQL と `DATABASE_URL` が必要。`npm run db:migrate` を先に行う。E2E は `npm run build` の後に `npm run test:e2e`。

## Review Focus

1. **`shareId` がワークスペースの JSON に保存されてしまう** — `read` の応答のリストには `shareId` が付いている。`modify` がそのまま `write` に渡すと保存される。→ Task 3 のテスト「modify は shareId を保存しない」。
2. **Web 画面が開いている間の API 書き込み** — revision が競合したら、API はやり直して成功する。Web 側は次の保存で409を受け取り、読み込み直す。→ Task 3 のテスト「modify は競合時にやり直す」。
3. **他人・期限切れ・失効したトークン** — どれも401になる。他人のトークンIDを `DELETE` すると404。→ Task 3 の `verify`・`revoke` テストと、Task 4 の E2E。
4. **共有中のリストの単語を API で置き換える** — 公開リンク `GET /api/shared/<id>` が新しい単語を返す。→ Task 3 のテスト「modify で共有テーブルも更新される」。
5. **`since`・`limit` の不正な値、`id` や `wordCount` のない古い記録** — `since=abc`、`limit=0`、`limit=1001`、`limit=1.5` は `400 invalidQuery` にする。古い記録もそのまま新しい順に返す。→ Task 2 の `selectRecords` テスト。
