# 画面をまたぐ部品の共通化 Implementation Plan

> この計画は実装済みの記録です。書かれている構成・パス・手順は当時のもので、今の構成は [README](../../../../README.md) を見てください。ここから作業を始めないでください。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** メニュー、空の状態、検索欄を `src/components/ui/` の部品にまとめる。見た目と動作は変えない。

**Architecture:** 既存の `ui/popover.tsx` と同じ書き方で3つのファイルを作り、画面の呼び出しを置き換える。PR は部品の種類ごとに3つで、順に merge する。

**Tech Stack:** Next.js、React、TypeScript、Tailwind CSS、`radix-ui`、`cn`

**Spec:** `docs/superpowers/specs/2026-11-04-shared-ui-design.md`

## Global Constraints

- `tests/e2e/` と `src/messages/` を変えない。E2E を直したくなったら動作が変わった合図なので、部品の側を見直す。
- 対象の要素に当たるクラスの集合を変えない。順序の違いと、部品が足す `data-slot` だけを許す。
- 翻訳キー、DOM の入れ子、`id`、既存の `data-*`、`aria-*`、`onCloseAutoFocus` などの props を変えない。
- 新しい依存、Context、状態を足さない。翻訳は部品に持ち込まない。見つけたバグは直さず記録する。
- 新しいファイルは200行以下とする。`import { cn } from "@/lib/utils"` ではなく、隣の `ui/` のファイルと同じ書き方に合わせる。
- `cn` は同じ種類のクラスの後の方を残す。既定と衝突するクラスを `className` で渡すと既定が消えることを前提に確かめる。
- コミットメッセージと PR は日本語で書き、コミットの末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` を、PR の本文の末尾に `🤖 Generated with [Claude Code](https://claude.com/claude-code)` を付ける。
- PR のタイトルは日本語の1文で、末尾に `(vX.Y.Z)` を付ける。
- ブランチは `git switch --no-track -c <名前> origin/main` で作る。push は `-u` を付けない（サンドボックスが `.git/config` への書き込みを止めるため）。
- 確認のコマンドは `npm run typecheck`、`npm test`、`npx eslint src tests --max-warnings 0`。`npm run lint` は `.claude/worktrees` のビルド出力を拾うので使わない。`npm run build` と E2E は手元で動かせないので、PR の `verify` に任せる。

## Review Focus

部品は単体テストから読まれず、E2E を変えない約束なので、次は各 PR の最後のタスクで、手元の画面を操作して確かめる。

1. 練習の画面で端末のメニューを閉じると、入力欄にフォーカスが戻る（Task 4）。
2. 削除の項目は、通常とハイライトのどちらでも赤く、`ListRow` と `PackRow` ではアイコンも赤い。ダークモードでも同じ（Task 4）。
3. `asChild` の項目（`ListRow` の「このリストを練習」、`DeviceMenu`、`AccountBar`）がリンクのまま動く（Task 4）。
4. 最後のリストを削除したあと、`empty-heading` にフォーカスが移る。#241 の修正が `EmptyState` の置き換えで壊れていない（Task 6）。
5. 消すボタン付きの検索欄で、文字を入れるとボタンが出て、押すと検索語が消える（Task 8）。

### Task 1: 部品を作り、操作のメニューを置き換える

**Files:**
- Create: `src/components/ui/dropdown-menu.tsx`
- Modify: `src/components/WordLists/ListRow.tsx`、`src/components/WordLists/PackRow.tsx`、`src/components/WordLists/WordRowFields.tsx`、`src/components/SortableListRow.tsx`

**Interfaces:**
- Produces（すべて `src/components/ui/dropdown-menu.tsx` の named export）:
  - `DropdownMenu`、`DropdownMenuTrigger`、`DropdownMenuRadioGroup`
  - `DropdownMenuContent`：`Portal` を含む。既定は `z-50 rounded-lg border bg-popover p-1 text-popover-foreground shadow-md`
  - `DropdownMenuItem`：`variant?: "default" | "destructive" | "inset" | "bare"`
  - `DropdownMenuRadioItem`、`DropdownMenuCheckboxItem`：既定は `inset` と同じクラス。`children` の前に `ItemIndicator` を持つ
  - `DropdownMenuLabel`：既定のクラスなし
  - `DropdownMenuSeparator`：既定は `my-1 h-px bg-border`

`variant` のクラス:
- `default`：`flex cursor-pointer items-center gap-2.5 rounded-md px-2.5 py-2 text-sm outline-none select-none data-[disabled]:pointer-events-none data-[disabled]:opacity-40 data-[highlighted]:bg-accent data-[highlighted]:text-accent-foreground [&_svg]:size-4`
- `destructive`：`default` に `text-destructive data-[highlighted]:text-destructive` を足す
- `inset`：`relative flex cursor-pointer items-center gap-2 rounded-md py-2 pr-3 pl-8 text-sm outline-none data-[highlighted]:bg-accent data-[highlighted]:text-accent-foreground`
- `bare`：既定のクラスなし

印は `<Primitive.ItemIndicator className="absolute left-2.5 inline-flex"><Check className="size-4" aria-hidden="true" /></Primitive.ItemIndicator>` とする。

- [ ] **Step 1: `src/components/ui/dropdown-menu.tsx` を作る**

`ui/popover.tsx` と同じ形で、`"use client"`、`data-slot`、`React.ComponentProps` を使う。`align` と `sideOffset` は既定値を持たない。

- [ ] **Step 2: 4つのファイルを置き換える**

`menuItem` の定数を消す。`ListRow` と `PackRow` は、`[&_svg]:shrink-0 [&_svg]:text-muted-foreground` をファイルの定数にして `className` で渡す。削除の項目は `variant="destructive"` とし、この2ファイルでは `[&_svg]:shrink-0 [&_svg]:text-destructive` を渡す。`sm:hidden` などの条件は `className` に残す。`min-w-52`、`min-w-56` は `DropdownMenuContent` の `className` で渡す。

### Task 7: 検索欄の部品を作り、置き換える

**Files:**

- Delete: `src/components/Practice/ListSearchField.tsx`

**Interfaces:**
- Produces:
  - `SearchField({ value, onChange, placeholder, ariaLabel, className })`：`value: string`、`onChange: (value: string) => void`。`<label>` の既定は `flex items-center gap-2 rounded-lg border px-3 text-muted-foreground focus-within:border-ring focus-within:ring-3 focus-within:ring-ring/50`。高さと外側の余白は `className` で渡す
  - `ClearableSearchField({ value, onChange, label, clearLabel, size, className, inputClassName })`：`size?: "default" | "sm"`。`label` は `sr-only` の文と `placeholder` に使う

`size` の値:
- `default`（`ListToolbar`）：アイコン `left-3`、入力 `h-10 pr-9 pl-9`、ボタン `right-2 size-7`
- `sm`（`RankingList`）：アイコン `left-2.5`、入力 `h-9 pr-8 pl-8`、ボタン `right-1.5 size-6`

それ以外の入力のクラスの違い（`bg-background` と `bg-transparent`、`dark:bg-input/30` など）は `inputClassName` で渡す。元のクラスを両方読んで、共通の部分だけを部品に持たせる。
