# 機能の仕様

Web 版の画面ごとの動作です。開発の手順とコードの構成は [README](../README.md) にあります。

## ログインなしで利用

未ログインでも練習、単語リストの作成・編集・削除・並べ替え、CSV/TSV取り込み、CSV書き出し、記録・ベスト記録、端末管理が利用できます。データはこのブラウザーのLocalStorage（`typle-r:guest-workspace:v1`）に保存します。ブラウザーのデータ削除で失われ、別端末には同期されません。

GitHubログインは任意です。ログイン時は従来のアカウント専用クラウド保存に切り替わります。両方のデータは分離され、自動コピーしません。ログアウトするとブラウザー側のデータに戻ります。クラウドAPIは引き続き認証必須です。

上部の「テーマ」からライト・ダーク・システムを選べます。初期設定はシステム（OSの外観に追従）です。選択はブラウザに保存され、再読み込みやページ移動後も維持されます。

## 表示言語（/settings）

サイドバーの「設定 › 一般」で、表示言語を日本語・English・简体中文・繁體中文・Русский・Français から選べます。選ぶとその場で画面全体が切り替わり、選択はCookie（`NEXT_LOCALE`、1年）としてこのブラウザーに保存されます。未設定のときは日本語です。URLは言語によらず同じで、単語リストや記録の内容は翻訳しません。

多言語化には [next-intl](https://next-intl.dev/) を使い、ロケールのルーティングは行いません（`src/i18n/request.ts` がCookieから言語を決めます）。画面の文言は `src/messages/<言語>/<領域>.json` にあり、コードに直接書きません。

- 文言はICU MessageFormatです。件数は `{count, plural, ...}` で各言語の複数形に合わせます。アポストロフィはICUの特殊文字のため、`’` を使います。
- 日本語のファイルが基準で、型（`src/i18n/next-intl.d.ts`）にもなります。キーを追加したら6言語すべてに追加してください。
- `src/core` と `src/plugins` は言語に依存しません。エラーは `AppError`（`src/core/appError.ts`）で `errors` のキーを返し、画面は `useErrorText` で表示します。日付・所要時間・端末名は `useFormat`（`src/i18n/useFormat.ts`）で整形します。
- `tests/i18n.test.cjs` が、全言語のキーとプレースホルダーの一致、ICUの構文、`src` に日本語の文言が直接書かれていないことを確認します。

## 入力（/input）

サイドバーの「設定 › 入力」で「特殊文字の簡易入力」をオン・オフできます（初期設定はオフ）。オンにすると、á・í・ñ・č・ů のようにアクセントやティルダなどの記号が付いたラテン文字を、記号のない文字（a・i・n・c・u）で入力しても正解になります。記号付きの文字をそのまま入力しても正解で、入力欄には記号付きの文字が入ります。ロシア語のキリル文字も、привет → privet、школа → shkola のようにラテン文字で入力できます。ß → ss、¿ → ? にも対応しています。かなの濁点や ¡ は対象外です。同じ画面の「大文字・小文字を区別しない」（初期設定はオフ）をオンにすると、A と a、É と é のように大文字と小文字を同じ文字として扱います（v2.3.0 から）。両方オンにすると、É を e で入力しても正解になります。どちらも入力欄には単語の文字が入ります。判定は `src/core/typing.ts` の `matchesCharacter` で、設定はこのブラウザーの LocalStorage（`typle-r:simple-special-input`・`typle-r:ignore-case`）に保存します。

ロシア語の簡易入力の対応表です。複数キーの途中では文字を確定せず、すべて入力すると元のキリル文字が入力欄に入ります。打ち間違いはミスとして数え、続きから入力できます。大文字は先頭を大文字（Ш → Sh）またはすべて大文字（Ш → SH）にします。「大文字・小文字を区別しない」がオンなら小文字でも入力できます。

|---|---|---|---|---|---|
| а | a | б | b | в | v |
| г | g | д | d | е | e |
| ё | yo | ж | zh | з | z |
| и | i | й | y | к | k |

## 初めての人向けのページ（/）

`/` は、初めて来た人に Typle を紹介するページです（v2.31.0 から。それまでは `/home` へ移るだけでした）。検索エンジンに中身が見えるよう、サーバーで描画します（`src/app/page.tsx`、文言は `src/messages/*/landing.json`）。ログインしているかどうかにかかわらず、だれにでもこのページを出し、ホーム（`/home`）へのリンクを置きます。

- 見出しと「ログインせずに練習を始める」（`/play`）・「公式パックを見る」（`/packs/catalog`）・「ホームへ」
- 見出しの横で、その場で1語打てます（v2.40.0 から。`src/components/Landing/TryWord.tsx`）。単語は公式パック「英語：基礎」の最初のリストの先頭10語で、意味（注釈から単語を除いたもの、`wordMeaning`）を下に出します。打ち終えると次の語へ進み、1語打つと下の「このパックで練習を続ける」が主ボタンになります。押すと公式パックのページと同じ処理（`src/lib/useOfficialPackStart.ts`）でフォローし、`/play` で練習を始めます。ここで打った分は記録しません。文言は `landing.try` で、このページの文言のうちこれだけはブラウザに送ります（`src/i18n/messages.ts` の `clientMessages`）
- 公式パック：プログラミングと語学に分けて、公式リストの数と主な内容を出します。それぞれ実際の単語を3つ並べます（Linuxコマンド：基本、英語：基礎と中国語：HSK5級レベル単語の最初のリストから）。数は公式リストのカテゴリから数えます（`src/core/landing.ts`）。公式リストを足すと自動で変わりますが、カテゴリが「プログラミング」「語学」以外のリストを足したときは、このページの分け方も見直してください（`tests/landing.test.cjs` が知らせます）
- できること：自分の単語リスト・思い出して打つ・記録
- データの保存先と、使い方・Typleについてへのリンク

sitemap.xml では `/` の優先度を一番高くしています。

## パックがないときの練習画面（/play）

パックを1つも持っていないとき、`/play` は練習の代わりに、始めるための公式パックを3つ並べます（v2.39.0 から。それまでは「まだパックがありません」の1行だけでした）。

- 並べるパック：英語：基礎・中級、Linuxコマンド：基本、中国語：HSK5級レベル単語の順。1つ目を主ボタンにします。並びは `src/plugins/packs/starters.ts` の `STARTER_CATALOG_IDS` で、どれも公式パックにあることを `tests/packCatalog.test.cjs` で確かめます
- 各カード：パック名、リスト数と語数、最初のリストの名前と最初の3語、「このパックで始める」
- 「このパックで始める」：公式パックのページの「このパックで練習する」と同じ処理（`src/lib/useOfficialPackStart.ts`）で、パックをフォローし、最初のリストで練習を始めます
- 下に「ほかの公式パックを見る」（`/packs/catalog`）と「自分のパックを作る」（`/packs/create`）
- ホームの案内（記録が0件のとき）も「公式パックで練習を始めるか…」にしています

## アクセント色

色の役割を分けるため、青を1色だけアクセントにしています（v2.39.0 から。それまでは灰色だけでした）。`src/app/globals.css` の `--primary`・`--ring`・`--sidebar-primary`・`--sidebar-ring` で、ライトは `oklch(0.505 0.15 256.33)`（白い文字と 5.9:1）、ダークは `oklch(0.704 0.115 255.54)`（暗い文字と 6.9:1）です。主ボタン（`Button` の `default`）・サイドバーの現在地の線・ロゴ・練習の進捗バー・今打つ文字の下線・フォーカスの枠がこの色になります。主ボタンはダークモードでもアクセントにし、ホバーは 90% にして文字のコントラストを保ちます。サイドバーの今いる項目は、アクセントを 10% 敷いた地にアクセントの文字です（v2.40.0 から。地との比はライト 4.95:1・ダーク 5.86:1）。ホームの「記録を見る」は、主ボタン・枠のボタンと並ぶ3つ目の操作なのでリンクにしています。正解の緑・ミスの赤・グラフの `--trend` は変えていません。

## ホームのダッシュボード

記録が1件以上あると、ホームに練習の状況を表示します（0件のときは従来の案内）。集計は `src/core/dashboard.ts` にあり、日付・週（月曜はじまり）は端末のローカル時刻で区切ります。

- 続きから（v2.41.0 から。`src/components/Dashboard/ContinueCard.tsx`）：一番上に、最後に練習したリスト（どのモードの記録でも、一番新しい記録のリスト。単語のないリストは除く。`continueList`）を出します。リスト名、語数、最終練習日、通常のベスト（正確率・所要時間）、最初の3語と「ほか N 語」、「練習する」（`/play?list=<id>`）と「別のリストを選ぶ」（`/edit`）です。このカードに主ボタンがあるので、見出しの横の「練習する」は、続きのリストがないときだけ出します
- 苦手な単語（v2.42.0 から。`src/components/Dashboard/WeakWords.tsx`）：リストごとに、直近10回（`WEAK_RUNS`）の通常と思い出して打つ記録で間違えた単語を、間違えた回の数が多い順（同じなら間違えた回数の合計、次にリストの順）に並べます（`weakWords`）。苦手な単語の多いリストから3つまで、1リストに6語まで出し、残りは「ほか N 語」です。Handwriting の記録は数えません（書けなかった語は打ち間違えた語と意味が違うため）。今のリストにない単語（編集で消した単語）も数えません。「苦手な N 語だけ練習する」は `/play?list=<id>&review=weak` で、そのリストの苦手な単語だけを、結果画面のおさらいと同じく記録せずに練習します
- 今週のまとめ：今週の練習回数・連続練習日数・直近10回の平均正確率・練習時間。増減は先週の同じ曜日・時刻までと比べます。
- 次に練習するリスト：記録なし、3日以上練習していない、直近5回の平均正確率が90%未満のリストを順番に1件ずつ選び、最大3件。「練習する」は `/play?list=<id>` でそのリストを選んだ状態で開きます。
- リスト別の推移：最後に練習した順に、1単語あたりの秒数（所要時間÷単語数）と正確率を直近20回まで表示します。単語数・正確率がない古い記録はそのグラフから除外します。

「バージョンと開発」の「ライセンス」から開きます。Typle が配布しているほかの人のソフトウェア（本番の npm の依存。`package-lock.json` で `dev`・`devOptional` の付いていないもののうち、その環境に入ったもの）と、npm から来ないもの（next/font がビルドで取り込むフォントの Noto Sans JP、手書きパッドの韓国語の認識モデル）の名前・版・ライセンスを一覧にし、名前・ライセンスで絞り込めます。名前からはそれぞれのプロジェクトのページを開きます。ライセンスの全文は「すべてのライセンス文」（`/licenses/third-party.txt`）にまとめています。

## Typle Handwriting（手書き練習）

単語を見本（`display`）を見ながら手で書き写して覚える、タイピングと並ぶ練習のモードです（v2.10.0 から）。

- **名前とデータの値**：画面での名前は「Handwriting」（どの言語でも英語のまま）です。保存するデータ・API・URL の値は、iPad・Mac のアプリと共有するため `writing` のままです（リストの項目 `writing`、記録の `mode: 'writing'`、`?mode=writing`）。
- **リストの印**：リストの編集画面の「手書き練習（Typle Handwriting）に使う」をオンにすると、リストに印（`writing`）が付き、認識の手がかりになる言語（英語・日本語・中国語（簡体・繁体）・韓国語・フランス語・ドイツ語・スペイン語・ロシア語・チェコ語）を選びます。切り替えをオンにしたときの言語の初期値は表示言語に合わせます。印のないリストは Handwriting に使えません。印はパックのファイル・共有・パックの複製にもそのまま写ります。公式リストも印を持てます。フォローしたパックのリストの印は、ほかの項目と同じく公式リストに合わせます（v2.11.0 から。公式パックの「中国語：HSK6級 手書き単語1〜25」と、v2.25.0 からの「韓国語：手書き初級単語」、v2.27.0 からの「韓国語：手書き中級単語」「韓国語：手書き上級単語」、v2.28.0 からの「韓国語：手書き初級単語2」「3」、v2.38.0 からのタイピング用の「中国語：HSK5級レベル単語」「中国語：HSK6級レベル単語」に付いています）。
- **始め方**：`/play` で印の付いたリストを選ぶと「タイピング／Handwriting」の切り替えが出ます。選んだモードは、リストを選び直しても同じ選択のまま、このブラウザーに1つ保存します（`typle-r:writing-mode`。Handwriting のときだけ書きます）。印のないリストでは常にタイピングです。練習の途中で切り替えると、リストを切り替えるときと同じ確認（「練習を中断しますか？」）を出し、「練習を続ける」ならそのまま続けます。Handwriting からタイピングに戻したときは、タイピングの入力欄が出てからフォーカスを移します。
- **思い出して打つモードとの関係**：Handwriting は「思い出して打つ」と一緒に使えません。Handwriting を選んでいる間は「思い出して打つ」のボタンを隠します。「思い出して打つ」が入っていても Handwriting は選べ、その練習は Handwriting になります（「思い出して打つ」の選択は残り、タイピングに戻すとまた効きます）。

### 入力の手段

| アプリ | 画面に書く | OS の手書き入力 |
|---|---|---|
| Web | 韓国語のリストだけ（v2.26.0 から） | あり |
| iPad・Mac（typle-ipad v0.63.0 から） | あり | あり |

Web は OS の手書き入力（Windows の手書きパネル、Android の手書きキーボード、IME の手書きなど）が基本です。ブラウザーに標準の手書き認識がないため、v2.26.0 から、アプリが自分で読める言語（いまは韓国語だけ）のリストでは、アプリの中の「手書きパッド」も使えます（iPad には韓国語の手書きキーボードがないため）。画面に書く入力は iPad・Mac のアプリ（typle-ipad）にもあり、指・ペン・マウス・トラックパッドで書いた字を端末の中の Vision で読み取ります。端末の Vision がリストの言語を読めないときは、OS の手書き入力（iPad のスクリブル、Mac のトラックパッドの手書き入力）だけになります。照合の規則と記録の形は Web と同じです。入力欄の `lang` にはリストの言語を入れ、自動補完・自動修正・スペルチェックは切ります。スマートフォンは将来の対象です。今のままでも動く見込みですが、狭い画面に合わせた画面と動作の確認はそのときに行います。

### Web の手書きパッド（v2.26.0 から）

- **出る条件**：リストの言語の認識モデルをアプリが持っているとき（いまは韓国語）。Handwriting の練習で「手書きパッド／入力欄」の切り替えが出ます。初期値は手書きパッドで、入力欄を選ぶとこのブラウザーに保存します（`typle-r:writing-input`。`field` のときだけ書きます）。
- **読み取り**：サーバーにも OS にも送らず、ブラウザーの中で読みます。書いた線を高さ48pxの1行の画像にし、PaddleOCR の韓国語の認識モデル（`korean_PP-OCRv5_mobile_rec`、ONNX、約13MB）を [onnxruntime-web](https://onnxruntime.ai/)（WebAssembly、1スレッド）で動かします。モデルは `public/handwriting/`（出どころとライセンスは同じ場所の README）、実行環境の WebAssembly（約15MB）は `npm install` とビルドのたびに `scripts/copy-handwriting-runtime.cjs` が `public/handwriting/ort/` にコピーします。どちらも手書きパッドを最初に出したときに読み込み、そのページを開いている間は使い回します。読み込みに失敗したら「もう一度読み込む」と入力欄の切り替えを出します。
- **お手本に寄せた判定**：書き写す語は分かっているので、モデルの一番の読み（貪欲な CTC の復号）が違っていても、お手本の語の確率（CTC の前向きアルゴリズム）が一番の読みより対数で `ACCEPT_MARGIN`（3）以内に低いだけなら、お手本の語と読んだことにします（`src/core/handwriting.ts`）。語の間の空白の有無は問いません。公式の「韓国語：手書き初級単語」90語を手書き風の3書体で書いた画像で測ると、正しく書いた語を受け入れるのは約97%（一番の読みだけなら約89%）、字母1つだけ違う語（싸다→사다 など）を受け入れてしまうのは約0.7%、別の語は0%でした。
- **1語の流れ**：線を書き終えて0.6秒たつと黙って読み、一致すれば次の語へ進みます（入力欄の入力と同じ）。「判定」（Enter）はすぐに読み、一致しなければミスを1つ数えて「〇〇と読めました」を出します。読みの途中経過は「いまの読み取り：〇〇」と出します。「1画戻す」（⌘Z・Ctrl+Z）と「消す」で書き直せ、Esc は最初からやり直します。計時は最初の1画から始めます。
- **ペンと指**：ペン・指・マウスで書けます。一度ペンで書くと、そのページでは指の接触を手のひらとみなして無視します。

### 照合の規則

`src/core/writing.ts` の `matchesWriting` が、入力と `display` の両方を次のとおりそろえて比べます。

1. NFC に正規化する
2. 前後の空白を除き、続く空白を1つにする
3. 言語が日本語・中国語（簡体・繁体）のときは、空白をすべて除く

「特殊文字の簡易入力」「大文字・小文字を区別しない」の入力の設定は、タイピングと同じ規則で文字ごとに効きます。候補が複数あるときは、どれか1つでも一致すれば正解です。

### 1語の流れ

- 入力のたびに照合し、一致すればその場で正解にして入力欄を空にして次の語へ進みます。IME の変換中（`compositionstart` から `compositionend` まで）は照合しません。
- 「判定」（Enter）を押して一致しなければ、ミスを1つ数え、「〇〇と読めました」を出します。書き直せるよう、入力欄の文字は残します。入力欄が空のときの Enter は何もしません。
- 「飛ばす」はいつでも押せます。ミスを1つ数えて次の語へ進みます。
- 計時は最初の入力から最後の語が終わるまでで、フォーカスが外れている間は止めます。
- 最後の語が終わると、タイピングと同じ結果画面に「Handwriting」の表示を付けて出し、記録を保存します。

### 記録と集計の分け方

記録には `mode: 'writing'` を付けます。記録の `mode` は、省く（通常のタイピング）、`'recall'`（思い出して打った記録）、`'writing'` の3つだけで、`null` を含むほかの値は Web・サーバーとも不正な記録として拒否します。`mistakes` は「判定」で一致しなかった回数と「飛ばす」の回数の合計です。`accuracy` は、正しく書けた語の数 ÷ 判定した回数 × 100、つまり（単語数 − 飛ばした数）÷（単語数 ＋ 一致しなかった回数）× 100 です。飛ばした語はミスに数え、正しく書けた語には数えません。たとえば2語のうち1語を飛ばし、もう1語を1回で書けたときは 50 です。どの手段で書いたかは残しません。

- ベストと順位は、通常・思い出す・Handwriting の3つのモードで別に付けます（結果画面のベストとの差、練習画面の右のベスト、リストの選択肢のベスト、練習記録の「ベスト」の印、ベスト記録ページ）。ベスト記録ページは「通常／思い出す／Handwriting」の切り替えで見分けます（URL は `?mode=recall`・`?mode=writing`。通常は付けません）。ベスト記録ページの詳細の記録数・「この端末の記録がありません」の表示と件数・端末を変えたときに開いたリストを残すかどうかも、選んだモードの記録だけで決めます。
- ホームのダッシュボードでは、思い出して打った記録と同じく、今週の回数・練習時間・連続日数に数えます。正確率の比較・次に練習するリスト（正確率の理由を含む）・リストの推移には数えず、通常の記録だけで比べます。
- 単語リストの一覧の練習回数・最終練習日には、思い出して打った記録と同じくすべての記録を数えます。ベストの比較に使う今の単語数の記録の数（`currentRecordCount`）は通常の記録だけです。
- 練習記録の一覧には Handwriting の記録も並び、「Handwriting」の印が付きます。リストで絞ったときの上のまとめのベストは、そのリストにあるモードごとに出します。
- アプリの `/api/workspace/records` は `recall` と `writing` を受け付けます。

## 単語リスト

サイドバーの「単語リスト」では、保存した単語リストを1行ずつ、単語の例・単語数・練習回数・最終練習日とともに表示します。リスト名と単語で検索でき、追加した順（新しい順）・最近練習した順・名前順・単語が多い順に並べ替えられます。各行の「編集」で編集画面を開き、「…」から練習・ベスト記録・練習記録・CSVエクスポート・複製・削除を選べます。複製は単語だけを写した「（コピー）」を作り、練習記録は写しません。自作のリストは150件まで保存できます（v0.76.0 から。それまでは100件）。v2.16.0 から、フォローした公式パックのリストはこの150件に数えず、公式パックは別に200個までフォローできます。フォローしたパックのリストは単語を保存しない（v2.1.0 から）ため、件数で抑える必要がないからです。一覧の見出しの横には「自作 n / 150」と「フォロー m / 200パック」を分けて表示します。保存の大きさは、これまでどおり件数とは別に抑えます。

編集画面は `/edit?list=<id>` で開くため、再読み込みやブラウザーの戻るでも一覧と行き来できます。保存していない変更があるときは、キャンセル・戻る・タブを閉じる前に確認します。単語数を変えると、それまでの記録は残りますがベスト記録の順位に含まれなくなるため、保存バーで案内します。

## ギャラリー（/gallery）

ほかのユーザーが公開した単語パックを探して、中身を確かめてから自分のパックに追加できます（v2.7.0 から）。ログインなしで開けますが、検索エンジンには載せません（`noindex`）。公式パックのカタログ（`/packs/catalog`）の下と、サイドバーの「単語リスト」の中にリンクがあります。

上に検索欄、カテゴリの選択、並べ替え（新しい順・追加の多い順）があります。検索は名前・説明・タグへの部分一致で、大文字小文字を区別しません。条件は URL（`q`・`category`・`sort`）に入るため、再読み込みや共有でも同じ一覧になります。カードには名前・説明・カテゴリ・タグ・リスト数・単語数・追加数を出し、押すと共有リンクと同じ `/shared/<id>` で中身を確かめて「自分のパックに追加」できます。20件ずつ表示し、「もっと見る」で次を足します。1件もないときは、条件があれば「見つかりませんでした」、なければ「まだ公開されたパックはありません」と出します。読み込みに失敗したら「やり直す」を出します。

追加したパックは自分のコピーで、公開元が更新しても届きません。ギャラリーのパックを追加すると、そのパックの追加数が1増えます。作者の名前は出しません。

### パックを載せる・通報する・非公開にする（v2.9.0 から）

パックの「…」メニューの「共有」を開き、「ギャラリーに載せる」をオンにするとギャラリーに載ります（共有リンクを作っていなければ、同時に作ります）。ギャラリーはだれでも見られ、作者名は出ません。ダイアログにその注意と、カテゴリを付けると見つけてもらいやすい旨を出します。載せたパックには、パックの行に「ギャラリーに掲載中」と表示します。オフにするか共有をやめると、ギャラリーから消えます。

ギャラリーや共有リンクの `/shared/<id>` で開いたパックは、「通報」から理由（「不適切な内容」「スパム・宣伝」「個人情報」「その他」）を選んで管理者に送れます。ギャラリーに載っていない（リンクだけの）共有は通報できません。

管理者は `/admin` の「ギャラリー」の欄で、載っているパックと非公開にしたパックを通報の多い順に見て、載っているパックには「非公開にする」を、非公開にしたパックには「戻す」を押せます。非公開にされたパックは、ギャラリーからも `/shared/<id>` からも消えます。持ち主のパックの行には「非公開にされました」と表示し、持ち主はその共有をギャラリーに載せ直せません（パックの更新と共有をやめることはできます）。通報と追加数の連打は、IP ごとの回数制限で抑えます（通報は1分あたり10回、追加数は60回。超えると `429`。詳しくは README の「ギャラリーのレート制限」を参照）。

## 単語リストのCSVエクスポート

「単語リスト」の各リストの「…」から「CSVエクスポート」で、input・display・annotationの3列をUTF-8（BOM付き）で保存できます。単語の順番・重複・空白・改行を保持し、練習記録は含みません。既存のCSV取り込みで再利用できます（取り込みは1 MiB以内・1,000単語まで）。保存済みの内容を出力します。

## CSV・TSVから単語を追加

「単語リストを作成」または編集画面の「CSV・TSVファイルから追加」でUTF-8のファイルを選び、読み込んだ内容を確認・修正して保存します。入力中の単語は残し、末尾に追加します。リスト名が空の場合はファイル名を使います。

```csv
input,display,annotation
Japan,日本,国名
France,フランス,
```

`input` と `display` は見出し・各行の値とも必須です。`annotation` はカラム自体も値も省略できます。見出しの順番は自由で、その他のカラム名・重複した見出しはエラーになります。TSVではタブで区切ります。補足列の誤記 `anotation` も受け付けます。単語の前後空白・順序・重複は保存時にも保持します。引用符で囲ったカンマ・タブ・改行、二重引用符のエスケープ（`""`）、UTF-8 BOMに対応します。ファイル上限は1 MiB、単語数は1リスト1,000件です。

## 練習に使用した端末の記録

サイドバーの「端末」で端末名と配列・メモ（例：JIS、US、キーの入れ替え）を登録できます。「練習する」の使用端末を選んで練習すると、結果・記録・ベスト記録に練習時点の端末情報が残ります。練習開始後は端末を変更できません。端末の名前やメモを編集・削除しても、過去の記録は変わりません。

登録した端末はログイン中のアカウントに保存されます。使用端末の選択はブラウザー・アカウントごとに記憶するため、別の端末に選択状態は同期しません。どのアカウントにも組み込みの端末「デフォルト」があり、使用端末を選ぶまではこれで練習します（登録数には数えず、名前の変更と削除はできません）。使用中の端末を削除すると「デフォルト」に戻ります。端末を記録しないときは「未選択」を選びます。未選択での練習と従来の記録は「未記録」と表示します。

「端末」画面では、このブラウザーで練習に使う端末（「練習する」の端末メニューと同じ設定）を変更でき、端末ごとの練習回数と最後に練習した日を確認できます。回数は記録に残した端末IDで数えるため、名前を変えた後も引き継がれます。このブラウザーで使う端末が「デフォルト」か未選択のときに追加した端末は、そのまま練習に使う端末になります（追加時に選択を外せます）。端末は100台まで登録できます。

ローカルでは `npm run db:migrate` で `0002_practice_devices` を適用してください。Vercelではビルド前にマイグレーションを実行し、失敗した場合は新しいアプリを公開しません。既存 workspace に空の端末一覧を追加する migration です。

## 結果画面の間違えた単語

練習を終えた結果画面に、間違えた単語を出します（v2.41.0 から。`src/components/Practice/MissedWords.tsx`）。

- 4つ目の欄は「間違えた単語」で、間違えた語数と全体の語数（`2 / 40 語`）です。それまでは単語数でした。下の端末名はそのままです
- 一覧：練習した順に、単語（表示と入力が違う語は両方）、意味（注釈から単語を除いたもの、`wordMeaning`）、最初に間違えたときのこと、間違えた回数を並べます。最初に間違えた文字には赤い下線を引きます
  - タイピング：「6文字目で a と打った」。空白は「スペース」と書きます
  - 思い出して打つ：答えを見た語は「答えを見た」（間違えたキーがなくても並べます）
  - Handwriting：「「xy」と書いた」、飛ばした語は「飛ばした」。回数は判定で違った回数です
- 間違えた単語がないときは「間違えた単語はありません。」の1行だけにします
- 「間違えた N 語だけ練習する」：その語だけを、同じやり方（タイピング・Handwriting、思い出して打つ）でもう一度練習します。このおさらいは記録せず、練習中は上に「間違えた N 語のおさらい（記録しません）」と出します。おさらいの結果でも、間違えた語だけをさらに練習できます。「もう一度」や別のリストを選ぶと、リスト全体の練習に戻ります
- 単語ごとの間違いは、その回の練習の中で持ちます（`TypingSession.wordMistakes`）。何文字目で何を打ったかは結果画面のためだけで、記録には単語と回数だけを残します（下の「苦手な単語」）

### 記録に残す間違えた単語

v2.42.0 から、記録は間違えた単語を `missed` に持ちます（`[{ "word": 入力する文字, "count": 回数 }]`、間違えた回数の多い順に20語まで。`MAX_MISSED_WORDS`）。

- 単語は並び順ではなく入力する文字で持ちます。リストを編集・並べ替えても、同じ単語を指せます。
- 回数は、打ち間違えたキーの数か、Handwriting で違った答えの数です。答えを見た・飛ばした単語は、間違えたキーがなくても1回と数えます。
- 間違えた単語がない記録と、v2.42.0 より前の記録は `missed` を持ちません。
- アカウントの記録（Go、`server/internal/workspace` の `decodeMissed`）と、ブラウザーの記録（`src/core/records.ts` の `isMissedWords`）は、同じ規則で確かめます（`tests/fixtures/records/missed*.json`）。DB は記録を JSONB のまま持つので、マイグレーションはありません。

## ベスト記録

サイドバーの「ベスト記録」では、単語リストごとの自己ベスト・直近5回の平均・平均正確率・所要時間の推移（直近20回）と上位の記録を表示します。一覧は最近練習した順・名前順・記録が多い順に並べ替えと検索ができ、まだ記録のないリストもここから練習を始められます。順位の基準（正確率を優先／速さを優先）と端末での絞り込みを切り替えられ、`/rankings?list=<id>&device=<id>&order=speed` のようにURLに残ります。

リストの単語数を変えた後は、今の単語数で練習した記録だけを比べます。単語数が違う記録（編集前の記録や、単語数を保存していない古い記録）は「含めて表示」で順位に加えられます。今の単語数の記録が1件もないときは、すべての記録で順位を付けます。練習画面の結果・ベスト記録、「練習記録」のベストの印、ホームも同じ基準です。

## OGP・共有画像

Open GraphとXの大きな画像カードに対応しています。共通画像は `public/og-image.png`（1200 × 630 PNG）、タイトル・説明・代替テキストは `src/app/layout.tsx` に定義しています。

画像の絶対URLには `SITE_URL`（任意、`src/lib/siteUrl.ts`）、次に `AUTH_URL` を使用し、未設定なら `VERCEL_PROJECT_PRODUCTION_URL`、ローカルでは `http://localhost:3000` にフォールバックします。本番ビルド時は `AUTH_URL` を公開サイトのHTTPS URLに設定してください。共有先のクローラーがページと画像へ認証なしでアクセスできる必要があります。

## 公式パックのページ（/packs/<slug>）

検索から公式パックを見つけてもらうため、公式パックごとのページを作ります（v2.36.0 で10パック、v2.37.0 から全部の公式パック）。ビルドのときに作る静的なページで、検索エンジンにも中身が見えます。

- 中身：パック名・カテゴリとタグ・説明・リスト数と語数、「このパックで練習する」、リストごとの全部の言葉（打つ言葉と意味・補足）、公式パックの一覧へのリンク
- 「このパックで練習する」：まだフォローしていなければフォローし、最初のリストで `/play` を開きます。フォロー済みならそのまま開きます。フォローできる数（`MAX_FOLLOWED_PACKS`）に達しているときは押せず、理由を出します
- ページを持つパックと説明文は `src/plugins/packs/pages.json` に手で書きます（`slug`・`catalogId`・`description`）。説明はパックの中身に合わせて書き、40〜160字にします。`slug` は英小文字・数字・ハイフンで、`/packs` のほかのページ（`catalog`・`create`・`edit`）と重ならないようにします。どれも `tests/officialPackPages.test.cjs` で確かめます
- 同じ単語をレベル別に分けただけのパック（`arch-linux-commands-by-level` など）は、`pages.json` の `canonical` に元のパックのページを書きます。そのページの canonical は元のページを指し、sitemap.xml には載せません。どの公式パックにもページがあることも、テストで確かめます
- sitemap.xml に `canonical` のないパックのページを全部載せ（優先度0.7）、公式パックの一覧（`/packs/catalog`）の各パックにも「詳しく見る」のリンクを出します
- 一覧にないスラッグは404です

## 練習結果を X でシェア

練習結果の画面の「X でシェア」で、結果を X に投稿できます（v2.34.0 から）。X の投稿画面（`https://x.com/intent/post`）が新しいタブで開き、文と、結果のページへのリンクが入った状態になります。投稿する前に文を直せます。

- 結果のページ（`/result`）：リンクのクエリに結果そのもの（リスト名・所要時間・正確率・速度・単語数・モード）を入れ、サーバーに何も保存しません。値はすべて `src/core/sharedResult.ts` で範囲を確かめ、読めないリンクには「記録を表示できません」を出します。リスト名は1行にして60文字までにします
- 結果の画像（`/result/image`）：X などでリンクを貼ったときのカード画像（1200×630）を、その場で描きます（`next/og`）。文字は Google Fonts の Noto Sans（日本語・中国語・韓国語・ラテン・キリル文字）から、描く文字だけを取り寄せます。取り寄せられなかったときも画像は出ます。画像はクエリだけで決まるので、CDN に長く置きます
- 結果のページは `noindex` です。リンクごとに別のページになり、中身も少ないためです
- リスト名は、シェアした人が自分で投稿するときだけリンクに入ります。アクセス解析はクエリを送らないので、解析にリスト名は残りません

## ページのタイトルと説明

どのページも「ページ名 | Typle」をタイトルにします（v2.32.0 から）。ページ名は、サイドバーのリンクやページの見出しで使っている言葉をそのまま使い、6言語でそろえます。クライアント部品のページは、そのフォルダーの `layout.tsx` から `src/lib/pageMetadata.ts` の `pageMetadata` で設定します。

- 説明（description）：検索から来る人がいるページ（`/play`・`/packs/catalog`）だけ専用の文にし、ほかはサイト全体の説明のままです（`PAGE_DESCRIPTIONS`）
- 自分のデータだけを表示するページ（`/home`・`/records`・`/rankings`・`/edit`・`/words`・`/devices`・`/interests`・`/create`・`/packs/create`・`/packs/edit`）は `noindex, follow` にします。クローラーには空の画面しか見えないためです
- 新しいページを足したら、`PAGE_TITLES` にページ名のキーを足し、`layout.tsx` を置いてください。キーが全言語にあること、sitemap.xml に `noindex` のページがないことは `tests/pageMetadata.test.cjs` で確かめます

## 検索エンジン向けの sitemap.xml・robots.txt

`/sitemap.xml` と `/robots.txt` を返します（v2.29.0 から）。どちらも上の OGP と同じサイトの URL を使い、載せるページと除くページは `src/core/searchIndex.ts` に1か所でまとめています。

- sitemap.xml：ログインせずに開けて、だれが見ても同じ内容のページ（`/`・`/play`・`/packs/catalog`・`/guide`・`/about`）。ギャラリーは中身が入れ替わる検索ページなので `noindex` にしていて、載せません。練習記録やベスト記録のように自分のデータを表示するページは、クローラーには空の画面しか見えないため載せません。
- robots.txt：管理画面（`/admin`）、開発用ログイン（`/local-login`）、バックエンド（`/api/`）へのクロールを断り、sitemap.xml の場所を示します。

Google Search Console は「URL プレフィックス」のプロパティ（`https://typle-r-six.vercel.app`）で登録し、所有権は HTML タグで確認します（v2.29.1 から）。独自ドメインに移ってからは、`sparklingstadt.com` の「ドメイン」プロパティ（DNS の TXT レコードで確認）でも登録し、`https://typle.sparklingstadt.com/sitemap.xml` を送信しています。タグの値は `src/app/layout.tsx` の `GOOGLE_SITE_VERIFICATION` にあり、全ページの `<head>` に `google-site-verification` として出ます。秘密の値ではありません。消すと所有権の確認が外れるので、残してください。

ページを足したり名前を変えたりしたときは `INDEXED_PATHS` も直してください。載せたページの `page.tsx` があることは単体テスト（`tests/searchIndex.test.cjs`）で確かめます。

## アクセス解析（Vercel Web Analytics）

ページの表示数を Vercel Web Analytics で数えます（v2.30.0 から）。`src/app/layout.tsx` で全ページに `src/components/WebAnalytics.tsx`（`@vercel/analytics/next` の `Analytics`）を置いています。Cookie は使いません。`VERCEL=1`（Vercel 上で動いているとき）のときだけ置きます。スクリプトは Vercel だけが `/_vercel/insights` で配信するので、ローカルや CI の E2E で置くと404になるためです。

- 送る前に `src/core/analytics.ts` の `analyticsUrl` で、URL をオリジンとパスだけにします（`?` 以降と `#` 以降を除く）。ベスト記録の `?list=` などに入るリストのIDや絞り込みを送らないためです。
- 管理画面（`/admin`）と開発用ログイン（`/local-login`）の表示は送りません。
- 「Typleについて」の「不具合の報告」の節に、送る内容（ページのアドレス・参照元・ブラウザー・OS・国）を書いています。送る内容を変えたら、6言語の `about.json` の `reports.analytics` も直してください。

Hobby プランでは月50,000イベントまで無料で、超えると翌月まで収集が止まります（課金はされません）。集計の期間は1か月分です。有効にするには、Vercel のプロジェクトの「Analytics」タブで Web Analytics を有効にしてからデプロイします。
