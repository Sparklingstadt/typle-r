# ロードマップ

2026-11-07（v2.37.0）に、Web 版・Go のバックエンド・iPad／Mac 版（typle-ipad v0.65.0）の現状から決めた、これからの進め方です。何を作るかの順番と理由を書きます。リファクタリングの順番は [refactoring-roadmap.md](refactoring-roadmap.md)、保存の仕組みの改善は Issue [#174](https://github.com/Sparklingstadt/typle-r/issues/174) にあり、このファイルはそれらを含めた全体の順番です。

期間は「今」「次」「その先」の3段で、日付を細かく決めません。終わった項目は消し、月に1回この日付と内容を見直します。

| 段 | 期間 | 確からしさ |
|---|---|---|
| 今 | 2026年11月中 | やると決めたもの。範囲も決まっている |
| 次 | 2026年12月〜2027年1月 | やるつもりのもの。範囲は設計のときに決める |

## 現状

- **使われ方を測り始めたところ**：v2.29.0〜v2.37.0（11/5〜11/7）で、初めて来た人向けのページ、sitemap、公式パック71個ごとのページ、X でのシェア、Vercel Web Analytics、Search Console の登録を入れました。検索から来る人がどのページに着くかは、まだ数字がありません。
- **公式パックは271個**で、そのうち184個が Handwriting に使えます（中国語154・韓国語30。v2.38.0 から HSK5・6級レベル単語の4つを含む）。ブラウザーの中で手書きを読み取れるのは韓国語だけで、中国語は OS の手書き入力に頼っています。語学のタイピングのパックは英語・ロシア語が4つずつ、スペイン語・フランス語・ドイツ語は1つずつです。
- **練習のモードは3つ**（写して打つ・思い出して打つ・手書き）で、記録はリストごとの時間・ミス・正確率です。単語ごとに何を間違えたかは残していません。
- **土台はひと区切り**：v2.36.x で CI の検査（knip・staticcheck・カバレッジ）、Prisma の廃止、大きい画面の分割が終わりました。Web版は v2.41.1 で GraphQL から REST へ戻りました。iPad／Mac 版は 11/6 から GraphQL を使っているので、`/api/graphql` は iPad／Mac 版が REST へ戻るまで残します。
- **残っている設計上の宿題**は Issue #174 の後半（効果の計測、`records_split` の後始末、リストなどの操作の共通化、`schemaVersion`）と、デザインレビューで見送った小さな項目（デスクトップのサイドバーの折りたたみ、記録の削除の取り消し、ガイドの目次の現在地）です。

## テーマ

順番の理由になる3つの考えです。

1. **数字で決める**。使われ方を測る仕組みを入れたばかりなので、次に作るものは、その数字を見てから決めます。測る前に大きなものを作りません。
2. **覚える練習を深める**。Typle の中心は「覚えたい言葉を、打って覚える」ことです。打つ練習から、覚えたかどうかが分かる練習へ広げます。
3. **土台は小さく保つ**。使う人のいない経路と古い依存を残さず、1 PR に1項目で進めます。

計測の結果で順番を入れ替えます。入れ替える前の順番です。

| 項目 | 内容 | 決めること |
|---|---|---|
| 単語ごとのミスの記録 | 練習の結果に「どの単語で何回間違えたか」を残し、記録の画面とホームで苦手な単語を見せる。思い出して打つモードと手書きも対象 | 保存の形（記録の中に持つか、別のテーブルか）。Issue #174 の記録テーブルの上に足す |

| 公式パックの更新の反映 | 公式パックの単語や名前を直したとき、フォロー中のパックにも届くようにする（今は名前はフォローしたときのまま）。パック1つの練習を続けて行う「通しで練習」もここで検討する | 自分で変えた部分との扱い |
| 語学のタイピングのパックを増やす | 計測で人が来ている言語を優先する。候補は英語・ロシア語の上級、スペイン語・フランス語・ドイツ語の基礎単語・構文、韓国語のタイピング | 言語の順番（計測の結果で決める） |
| スマホでの Handwriting | 狭い画面に合わせた手書きの練習画面を作り、iPhone・Android のブラウザーで動作を確かめる | Android の手書きキーボードと手書きパッドのどちらを主にするか |
| 検索から来た人の受け皿 | 公式パックのページの説明と OG 画像をパックごとに整え、英語で説明しているパックは英語のページにする | 言語ごとに URL を分けるか（今は Cookie で言語を決めていて URL は同じ） |
| デザインレビューの残り | デスクトップのサイドバーの折りたたみ、記録の削除の取り消し、ガイドの目次の現在地 | なし。空いた時間に1つずつ |

## その先（2027年2月以降）

- **間隔反復（SRS）**：苦手な単語の記録を元に、復習する日を決めて出す。設計は「次」の結果が出てから。
- **REST の `/api/workspace` の削除**：終了予告から十分な期間（3か月を目安）を置いて消し、`server/internal/web` の包みを減らす。Android・Windows の古いアプリのログインの受け付け（`client=android|windows`）は残す。
- **ギャラリーの次の段**：作者名の表示、公開元の更新が届くフォロー。ギャラリーの表示数と追加数が伸びていたら。
- **Issue #174 の後半**：リスト・端末などの操作の共通化と全体保存の置き換え、`schemaVersion`、`WorkspaceContext` の分割。計測で保存時間や競合が問題になっていたら前へ出す。
- **手書きの次の言語**：日本語（かな・漢字）のモデル。パックがないので、パックと一緒に。
- **見本なしで書くモード**：意味から手で書く。思い出して打つモードの手書き版。

## やらないこと

- iPhone 版・Android 版のネイティブアプリ。アーカイブした typle-a・typle-w は直しません。スマホは Web で対応します。
- 評価・コメント、ほかのユーザーとの比較やランキング。
- 外部向けの API（`/api/v1` は v2.36.20 で消しました）。
- サーバーで画像を認識する手書き（費用と画像の送信を増やさない）。

## リスクと依存

| リスク | 影響 | 備え |
|---|---|---|
| 計測の数字が少なくて順番を決められない | 「次」の順番がそのまま | 11月末に数字が少なければ、順番を変えずに上から進める |
| 中国語の手書きモデルが大きい・精度が足りない | 「今」の項目が「次」へ | 入れる前にモデルの大きさと、HSK の単語で読み取れる割合を測る。足りなければ OS の手書き入力のままにして記録に残す |
| 単語ごとのミスの保存で記録のデータが増える | 保存時間と転送量 | Issue #174 の記録テーブルと計測の結果を先に見る。ページ送りのある記録テーブルに足す |
| 公式パックの更新を反映すると、自分で変えたリストが上書きされる | 練習する人のデータ | 変えた部分を残す規則を設計で決め、E2E で確かめてから出す |
| iPad／Mac 版の古い版が REST を使い続ける | 消すと古い版が動かない | 終了予告 → 期間を置く → 削除の順。公証のないアプリなので自動更新がなく、期間は長めに取る |
| GitHub Actions の支払い停止 | リリースが止まる | 11/1 に再開済み。止まったときは `CLAUDE.md` の手順で手で行う |

## 進め方

- 1 PR に1項目。機能はマイナー、直しとリファクタリングはパッチを上げます（`CLAUDE.md` の Release workflow）。
- 設計の要る項目は `docs/superpowers/specs/` に設計を書いてから始めます。範囲外に書いたことは、このファイルの「次」か「その先」に移します。
- 公式パックを変えたら typle-ipad の `catalog.json` を作り直します。GraphQL の変更は iPad／Mac 版と互換を保ちます。
- 月に1回（月末）、このファイルの「現状」と各段の項目を見直し、終わったものを消し、日付を更新します。
