## 現状の課題

| # | 優先度 | 課題 | 確認した内容 |
|---|---|---|---|
| 1 | P1 | 編集がページ上部のフォームで行われ、対象が分からない | 「編集」を押すと上部の共通フォームに値が入り、見出しが「端末を編集」に変わるだけ。対象のカードは枠・背景とも他と同じ。一覧が長いと上部までスクロールして位置を失う（390px で scrollY 353 → 289、100台なら最下部から最上部へ）。Esc で編集を取り消せない |
| 2 | P1 | エラーが日本語で出ず、欄に結びつかない | 空欄はブラウザー標準の吹き出し（英語環境では "Please fill out this field."）。空白だけの名前と101台目は「端末データの形式を確認してください。」（内部の検証文）。エラーは欄の下ではなく「端末を保存」の上に出て、欄は赤枠にならない（`aria-invalid`・`aria-describedby` なし） |
| 3 | P1 | 端末の使われ方が分からない | 一覧は名前と配列・メモだけ。何回練習したか、最後に使った日、「遊ぶ」で選んでいる端末がどれかが分からない。記録には端末IDが残っていて数えられる（確認データでは MacBook Air 7回、HHKB 3回、iPad 0回） |
| 4 | P1 | モバイルでカードの形がそろわない | 390px では編集・削除がテキストの下に回り、端末ごとにボタンの位置が変わる。長い名前のカードは 152〜212px。入力欄は幅 266px・高さ 32px で、プレースホルダーが「例：MacBook Air、デスクトップ-」で切れる |
| 5 | P2 | 登録済みでも追加フォームが一覧の上を占める | フォーム（高さ 228px）が常に最上部にあり、主な操作対象の一覧は y=517（1440）/ 569（390）から始まる |
| 6 | P2 | 削除ボタンが目立つ | すべてのカードに赤い「削除」が「編集」と同じ大きさで並ぶ（/create の課題 #7 と同じ） |
| 7 | P2 | 入力欄が小さい | 高さ 32px（/create の新デザインは 44px）で、隣の「端末を保存」（44px）とそろわない |
| 8 | P2 | 名前の変更と記録の関係が伝わらない | 記録には練習した時点の端末名が残るため、改名しても記録・ベスト記録は旧名のまま（MacBook Air → MacBook Air M2 にしても「MacBook Air（JIS）」）。削除の確認文には書いてあるが、編集時には説明がない |
| 9 | P2 | 保存の通知が一覧を覆う | 続けて3台追加すると通知が3件重なり（幅 1,008px・高さ 218px）、2〜3台目のカードの編集・削除ボタンが5秒間隠れる |
| 10 | P2 | 空の状態と説明に次の行動がない | 空のときは「端末はまだ登録されていません。」の1行だけ。説明文の「遊ぶ」はリンクではない。配列を書いていない端末に毎回「配列・メモなし」が出る |
| 11 | P2 | 保存先が表示されない | ブラウザー保存かアカウント保存かが分からない（/create には保存先のバッジがある） |

## 改善案

| 改善 | 対応する課題 | 内容 |
|---|---|---|
| 一覧を主役に、追加・編集はダイアログで | 1, 5 | 見出し「登録済みの端末 3台」の右に主ボタン「端末を追加」。フォームは常時表示しない。各行の鉛筆アイコンからその端末のダイアログを開く。Esc・キャンセルで閉じるとフォーカスは開いた行のボタンに戻る。保存した行は一瞬緑にして画面内に表示する |
| 欄ごとの日本語エラー | 2 | `noValidate` にして、「端末名を入力してください。」「「MacBook Air」はすでに登録されています。別の名前にしてください。」を欄の直下に出す。欄は赤枠（`aria-invalid`）にして `aria-describedby` でエラーを読み上げ、フォーカスを戻す。保存失敗・別画面での削除はダイアログ内の Alert |
| このブラウザーで練習に使う端末 | 3 | 「遊ぶ」の端末メニューと同じ設定（ブラウザー・アカウントごとの `localStorage`）を最上部のカードで表示・変更できる。ブラウザーごとに覚えることを説明し、「練習する」で /play へ。使用中の端末には一覧でも「使用中」バッジ。最初の端末を追加するときは「このブラウザーで練習に使う端末にする」を既定でオン |
| 練習回数と最後に練習した日 | 3, 8 | 記録に残した端末IDで数えるので、改名後も引き継がれる。「練習 7回 · 最終 今日」「まだ練習していません」 |
| 1行＝1端末 | 4, 6 | 名前・配列・メモ・練習回数を左、編集・削除（40px のアイコン）を右にそろえる。モバイルでもボタンは常に右上。削除は普段グレーで、ホバー時だけ赤 |
| 入力欄 44px | 7 | ダイアログの入力欄は /create と同じ 44px。プレースホルダーは短くし、書き方は欄の下の説明に移す |
| 記録への影響を先に説明 | 8 | 編集ダイアログに「名前を変えても、これまでの練習記録（7回）には練習した時点の名前が残ります」。削除の確認は「端末「X」を削除しますか？」とし、記録の回数と、使用中なら「未選択」に戻ることを出す |
| 空の状態 | 10 | アイコン・説明・「端末を追加」・入力例を出す。説明文の「遊ぶ」はリンクにする。配列・メモがない端末は何も出さない |
| 保存先のバッジ | 11 | 「このブラウザーに保存／アカウントに保存」を /create と同じ形で表示 |
| 上限 | 2 | 100台に達したら「端末を追加」を無効にし、「端末は100台まで登録できます。使わなくなった端末を削除すると追加できます。」を出す |

## 実装メモ

- 主な変更箇所: `src/app/(workspace)/devices/page.tsx`、`src/components/Devices/DeviceDialog.tsx`、`src/components/Devices/CurrentDevice.tsx`、`src/core/devices.ts`、`src/lib/deviceSelection.ts`、`src/components/DeleteConfirmation.tsx`
- 欄ごとのエラーは `deviceProblem()` が `{ field, message }` で返す。`saveDevice()` も同じ判定を使い、最初のエラー文を投げる。
- 練習回数は `deviceUsage()` で全リストの記録を端末IDごとに数える（最終日は記録の `date` の最大値）。
- 使用端末の選択は `useSelectedDevice(accountId)`（`typle-r:device:<accountId>`）にまとめ、/play と /devices で共有する。別タブでの変更は `storage` イベントで反映する。
- `DeleteConfirmation` は `open` を渡すとトリガーなしで使える。削除すると行ごと消えるため、閉じた後のフォーカスはページ側で「登録済みの端末」の見出しに移す。
- 保存の通知（`SaveNotification`）はアプリ全体の部品のため変えていない（課題 #9 は、保存した行のハイライトと画面内への移動で補う）。
