## 現状の課題

| # | 優先度 | 課題 | 確認した内容 |
|---|---|---|---|
| 1 | P0 | 保存エラーが画面外に出る | 同名リストのエラーはページ最上部に出る。4語を取り込んで下部の「保存」を押すと、スクロール位置 819px のまま画面が変わらず、無反応に見える |
| 2 | P2 | CSV取り込みが最上部を占有 | 主動線（リスト名→単語）の前に補助機能がある。ファイル選択はブラウザー標準の表示（英語環境では "Choose File / No file chosen"） |
| 3 | P1 | 必須エラーがブラウザー標準の吹き出し | 未入力で保存すると "Please fill out this field" の吹き出しだけが出る。欄に赤枠やメッセージは残らない |
| 4 | P2 | 説明文が常時2段落 | 保存先の説明とドラッグ操作の手順が本文に並び、フォームの開始位置が下がる |
| 5 | P1 | 「入力」「補足」ボタンが分かりにくい | 開閉状態の見た目の差がほぼない（背景色の差がごくわずか）。開くと1行が最大約209pxになる |
| 6 | P1 | 入力欄に単語がコピーされ、説明と矛盾する | 「入力」を開くと表示する単語が値として入っているのに、直下の説明は「空欄の場合は…」になっている |
| 7 | P2 | 操作列が重い | 並べ替えの手段がドラッグ・↑・↓の3つある。すべての行に赤いゴミ箱が並ぶ |
| 8 | P0 | Enterキーで即保存・画面遷移 | 単語欄でEnterを押すと、入力途中でも保存され /edit に移動する |
| 9 | P1 | 追加後にフォーカスが移らない | 「単語を追加」を押した後もフォーカスがボタンに残る |
| 10 | P1 | ボタンの優先度が同じ | 「単語を追加」「保存」「キャンセル」がすべて同じ黒の塗りボタン |
| 11 | P1 | 保存ボタンが最下部にある | 8語で保存ボタンの位置が 2,095px（モバイルでは 3,422px） |
| 12 | P0 | キャンセルで確認なしに破棄される | 入力途中でも即座に /edit へ戻り、入力内容が失われる |
| 13 | P1 | モバイルで入力欄が狭い | 390px幅で入力欄は 266px。ヘッダーが2段に折り返し、1語あたり約361pxになる |

P0 = データ損失・操作不能につながる／P1 = 迷い・手戻りが起きる／P2 = 見た目・情報設計

## 改善案

| 改善 | 対応する課題 | 内容 |
|---|---|---|
| 保存バーを画面下部に固定 | 1, 11 | 保存・キャンセル、「未保存の変更」、語数を常に表示する。保存に失敗したときはバーにエラー件数と「最初のエラーへ移動」を出す |
| インライン検証 | 1, 3 | `noValidate` にして、日本語のエラーを各欄の直下に出す。重複名はリスト名欄に出し、最初のエラー欄へスクロールしてフォーカスする |
| リスト名を最上部に、説明はバッジへ | 2, 4 | 保存先は「このブラウザーに保存／アカウントに保存」のバッジで示す。ページの説明は1行にする |
| CSV・TSVはダイアログで読み込む | 2 | 単語セクション右上のボタンから開く。ドラッグ＆ドロップ、書式例、プレビュー、「末尾に追加／置き換え」の選択を用意する |
| 3列を常時表示 | 5, 6 | 表示する単語・入力する文字・補足を1行に並べ、行の高さを52pxにそろえる。入力する文字は値をコピーせず、空欄のときは表示する単語をプレースホルダーで見せる |
| ハンドル＋「…」メニュー | 7 | ↑↓は「…」メニューに移し、Alt+↑↓でも動かせるようにする。削除アイコンは普段はグレー、ホバー時だけ赤にする |
| Enterで次の行へ | 8, 9 | Enterでは保存しない。最終行でEnterを押すか「単語を追加」を押したら新しい行を追加し、その単語欄にフォーカスする。IME変換中（`isComposing`）は無視する。保存は Ctrl/Cmd+Enter |
| ボタンの優先度を3段階に | 10 | 保存＝塗り、単語を追加＝破線、キャンセル＝ゴースト |
| 離脱時の確認 | 12 | 変更があるときは AlertDialog で確認する。既定のフォーカスは「編集を続ける」。タブを閉じる操作には `beforeunload` を使う |
| モバイルは1語＝1カード | 13 | ヘッダーを1行にする。表示する単語を全幅、入力する文字と補足を2列に並べる（1語あたり約180px）。`enterKeyHint="next"` を使う |

## 実装メモ

- `WordListEditor` は /create と /edit の両方で使っているため、改善は両画面に反映される。
- 主な変更箇所: `src/components/WordListEditor.tsx`、`src/components/SortableWordRow.tsx`、`src/components/WordListImport.tsx`、`src/app/(workspace)/create/page.tsx`
- 保存エラーは現在 `src/lib/wordLists.ts` が文字列の `Error` を投げている。欄ごとに表示するには、エラーの対象（リスト名／n行目）を返す形にする必要がある。
- 空行を保存時に除外する案（Figma の保存バー）は現在の挙動（空欄があると保存エラー）からの変更になる。採用するかは要判断。
- 確認ダイアログは既存の `src/components/ui/alert-dialog.tsx`、エラー表示は `ui/alert.tsx` を使える。
