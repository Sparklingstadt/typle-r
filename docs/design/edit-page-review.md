## 現状の課題

| # | 優先度 | 課題 | 確認した内容 |
|---|---|---|---|
| 1 | P1 | モバイルで操作ボタンが見えない | 390px では表（881px）が266pxの枠に入り、単語数・記録数・操作（編集・CSVエクスポート・削除）は表を横にスクロールしないと見えない。1行165px、ページ全体は1,837px |
| 2 | P1 | 編集画面に URL がない | 編集を開いても URL は /edit のまま。ブラウザーの戻るでアプリの外に出てしまい、編集中の内容も消える。再読み込みすると一覧に戻り、/rankings や /play からも直接開けない |
| 3 | P1 | 編集画面が途中から開く | 一覧を400pxスクロールしてから「編集」を押すと、編集画面も398pxの位置で開く。見出しとリスト名の欄が画面の外 |
| 4 | P1 | 削除の確認が汎用的 | 見出しは「削除してもよろしいですか？」。何語のリストで、練習記録が何件（英単語 基本は17件）消えるかが分からない。CSV で控えを取る導線もない |
| 5 | P1 | 読み込みエラーと空の状態が矛盾 | 保存データが壊れているとき、エラーの下に「単語リストがありません。」と空の表の見出し、作成リンクが出る。再読み込みの手段もない |
| 6 | P1 | 一覧に戻るとフォーカスが消える | キャンセル・保存・削除のあとフォーカスが body に落ち、キーボードでは先頭からやり直し。どの行を更新したかの目印もない |
| 7 | P2 | 1440pxでも操作が折り返す | 操作列（258px）に「編集」「CSVエクスポート」「削除」が入りきらず2段になり、1行113px。8リストで表の高さは948px |
| 8 | P2 | 操作の強さがそろっていない | 全行に黒の「編集」と赤の「削除」が並び、視線が操作に集まる。たまにしか使わない CSV エクスポートが一番幅を取る |
| 9 | P2 | リストの中身と使われ方が分からない | 名前・単語数・記録数だけで、「Test 1」「Test 2」のような名前では区別できない。単語の例・最終練習日がなく、練習・ベスト記録・練習記録への導線もない |
| 10 | P2 | 探せない・並べ替えられない | 並びは作成順で、新しいリストは一番下。検索もない（リストは100件まで保存できる） |
| 11 | P2 | 新規作成がテキストリンク | 「新しい単語リストを作成」は下線のリンクで、主な操作に見えない。説明文は CSV エクスポートの補足だけで、ページの目的が書かれていない |
| 12 | P2 | 見出し・レイアウトが新デザインとそろっていない | 見出しは24px・標準の太さ、カード1枚の古いレイアウトで、保存先のバッジもない。空の状態は1行と空の表見出し、読み込み中は文字だけ |
| 13 | P2 | 編集画面の文脈が足りない | タイトルは「単語リストを編集」だけで、一覧に戻る手段は下部の「キャンセル」だけ。単語数を変えると、これまでの記録がベスト記録の順位に入らなくなる（v0.24.0 の仕様）ことを知らせない |

P1 = 迷い・手戻り・入力内容の消失が起きる／P2 = 見た目・情報設計

## 改善案

| 改善 | 対応する課題 | 内容 |
|---|---|---|
| 見出し・説明・保存先 | 11, 12 | /devices と同じ太字の見出し「単語リスト」と1行の説明、保存先のバッジ。カード1枚の古いレイアウトをやめ、幅は最大1,024px |
| 件数と主ボタン | 11 | 「保存済みのリスト 8 / 100」と塗りの「新しいリストを作成」。100件に達したらボタンを無効にし、理由を出す |
| 検索と並び順 | 10 | リスト名と単語で検索。並び順は追加した順（新しい順・既定）／最近練習した順／名前順／単語が多い順。絞り込み中は「1件 / 全8件」 |
| 1リスト＝1行 | 7, 9 | 名前（長い名前は折り返す）・単語の例「apple・banana・… ほか6語」・単語数・「練習 17回 · 最終 今日」。1行77px、8リストの一覧は641px |
| 操作は3つ | 1, 8 | 練習（/play?list=）・枠線の「編集」・「…」。「…」はこのリストを練習（モバイル）・ベスト記録を見る・練習記録を見る（記録があるとき）・CSV エクスポート・複製・削除（赤） |
| 複製 | 9 | 単語だけを写した「（コピー）」を作る（練習記録は写さない）。一覧の先頭に出して緑で強調 |
| 編集は /edit?list=<id> | 2, 3 | 開くとページの先頭から表示。ブラウザーの戻る・キャンセル・保存で一覧の元のスクロール位置に戻り、その行の「編集」にフォーカス。保存した行は緑で2.4秒強調 |
| 未保存の変更を守る | 2 | ブラウザーの戻る・サイドバーの「編集」でも、キャンセルと同じ確認ダイアログを出す（URL は編集画面のまま）。タブを閉じる・再読み込みは `beforeunload` で確認（/create も同じ） |
| 編集画面の文脈 | 13 | 見出しの上に「‹ 単語リスト」、見出しの下に「12語 · 練習 17回 · 最終 今日」。単語数が変わるときは保存バーに「単語数が12語から13語に変わります。12語で練習した記録（12件）は残りますが、ベスト記録の順位には含まれなくなります。」 |
| 削除の確認 | 4, 6 | 「「英単語 基本」を削除しますか？」。消えるもの（12語 · 練習記録 17件（最終 今日））と、ダイアログ内の「CSV エクスポート」。削除後は次の行の「編集」へフォーカス |
| モバイル | 1 | 表をやめて横スクロールをなくす。1行＝名前・単語の例・「12語 · 練習 17回 · 最終 今日」、操作はアイコンの「編集」と「…」。ページは1,506px |
| 状態 | 5, 12 | 空の状態（説明と「新しいリストを作成」）、読み込みエラーは Alert と「再読み込み」だけ（空の状態を出さない）、読み込み中は一覧と同じ形のスケルトン、検索で見つからないときは「検索をクリア」、開こうとしたリストがないときは案内 |

## 実装状況

v0.25.0 で実装。

- 画面: `src/app/(workspace)/edit/page.tsx`（一覧・検索・並び順・削除の確認・状態、`?list=` と編集画面の行き来）、`src/components/WordLists/ListRow.tsx`（1行と「…」メニュー）
- 編集画面: `src/components/WordListEditor.tsx` に「‹ 単語リスト」、説明（`description`）、単語数が変わるときの注意、`beforeunload`、未保存の変更を外から確認する `cancelRequest`・`onDirtyChange` を追加。/create も「‹ 単語リスト」と `beforeunload` が付く
- ロジック: `src/lib/listOverview.ts`（使われ方の集計・並び順・検索・単語の例・複製・`MAX_LISTS`）。`src/lib/workspaceRequest.ts` の上限も `MAX_LISTS` を使う。CSV エクスポートは `downloadWordCsv`（`src/components/WordListExport.tsx`）にして、メニューと削除の確認から呼ぶ
- 決めたこと: 既定の並びは追加した順（新しい順）。単語の例は先頭6語。練習記録へのリンクは記録があるときだけ出す。複製の名前は「（コピー）」「（コピー2）」…で、200文字に収める
- テスト: `tests/listOverview.test.cjs`（集計・並び順・検索・単語の例・複製）、`tests/e2e/word-lists.spec.ts`（一覧・検索・並び順・メニュー、URL・戻る・未保存の確認・保存後のフォーカス、複製・削除、390px、空・読み込みエラー）。既存の E2E は「…」メニューからの CSV エクスポート・削除に合わせた

## 対象外

- アプリ全体のヘッダーが390pxで2段になる件と、56pxのサイドレール（他のレビューと共通の残課題）
- 保存の通知（`SaveNotification`）が画面下部の広い範囲を覆う件（/devices のレビューと共通）
- 編集中にサイドバーから別の画面（ホームなど）へ移ると、確認なしで未保存の変更が消える（/create と共通。今回はブラウザーの戻るとサイドバーの「編集」だけを確認する）
